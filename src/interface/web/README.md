# Карта и диспетчерский интерфейс

Текущая index.html/app.js работает с живым API. Сессию и роль определяет сервер;
URL не переключает аккаунт. Администратор видит весь план и получателей случаев,
диспетчер — свои случаи и адресованные передачи. Администратор их не обрабатывает.

Вкладки людей и транспорта сохраняют отдельные фильтры, сортировку и прокрутку.
Если временная вкладка людей исчезает у диспетчера 1/2, выбирается транспортная;
у диспетчера КПП и администратора вкладка остаётся доступна. Обработанные случаи
скрыты. Очистка архивирует представление и сохраняет серверные данные.

ИИ показывает очередь/выполнение и прошедшее время из queued_at/started_at
при штатном обновлении карточки, без нового таймера и выдуманного процента.
Повторная отправка во время анализа блокируется. Данные результата могут устареть;
это явно отмечается. Технические материалы сохраняются на сервере.

Карта читает site.json, позиции и датчики; не выдумывает их и не использует GPS.
Цвет обозначает владельца. Активная тревога имеет отдельный красный контур и !,
устаревшая позиция — янтарный пунктир и ?. Выбор карточки подсвечивает;
«Показать на карте» кадрирует обе машины столкновения, затем сопровождает основную.
Ручное движение карты, «Мой сектор» и «Весь план» прекращают сопровождение.

Polling выполняется без накопления раз в секунду, presence каждые 3 секунды.
PATCH использует увиденную dispatch_revision, 409 требует нового действия.
Ввод и получатель не пересоздаются при обновлении карточки; поздние ответы
проверяются по выбранному случаю, контексту и job_id.

Node проверки: tests/interface.test.js, tests/map-view.test.cjs,
tests/sensors-panel.test.cjs. dispatch-core.js/provider.js и tests/interface/*.cjs
остаются прежним mock/provider prototype, текущая index.html их не подключает.
Mock проверки не подтверждают SQLite, настоящий Qwen, браузер или целевой ноутбук.

## Посмотреть сейчас на Windows

1. Открыть PowerShell в корне клона Hackathon.
2. Выполнить:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory src/interface/web
```

3. Открыть `http://127.0.0.1:8765/?mode=mock&operator=dispatcher-1`.
4. Выбрать Склады, Производство или КПП. Включить «Общий журнал», если нужны остальные случаи. Кнопка «Ещё два случая на складах» проверяет видимость трёх случаев при открытой карточке. «Потеря позиции V1» показывает unknown без ложного восстановления. «Тест: восстановить условие» — только fixture, не команда реальному датчику.
5. Принять случай, написать результат и записать «Связался»/«Направил проверку». Активное или неизвестное условие не закрывается. Модельное подозрение можно отклонить с причиной, сохранив оценку и историю.

Mock хранится только в памяти одной вкладки. Перезагрузка сбрасывает fixtures. Три вкладки mock не являются тремя операторами общей БД. Готовность недоступна в mock, поскольку серверный lease не моделируется. Агент отключён; успешный анализ не подделывается. JS/CSS/SVG локальные; внешний интернет для просмотра не нужен.

## Подключить backend — Егор С. + Егор М.

Сервер должен обслуживать эту страницу и `/api` на одном origin. После его реализации: `http://127.0.0.1:8000/?mode=api&operator=dispatcher-1`. Другие профили — dispatcher-2/3. Простая команда http.server **не создаёт API**. Ошибка сервера не включает mock автоматически.

Provider использует health/site/operator-profiles, assets/incidents/sensors/dispatch-summary, v2 PATCH с X-Demo-Operator, expected_revision и request_id; presence session_id+availability, notifications cursor и agent jobs. Форматы в PREBUILD_FIXES. Новые record_response/dismiss_model реализует backend. Передачу/резервирование и их UI предстоит завершить по DISPATCH_OPERATIONS; наличие provider не доказывает готовность этих сценариев.

При ошибке обновления сохраняются последние данные с заметным сообщением. Карточка перечитывается, черновик результата сохраняется; устаревшие ответы прежнего профиля не перезаписывают новое рабочее место. Изменение выполняется после ответа сервера, без оптимистического назначения владельца. Звук включается человеком и ограничен одним сигналом за 5 секунд; история после старта не озвучивается.

## Файлы и проверки

- index.html/styles.css — структура и локальные стили.
- app.js — отображение/обновление/действия и переход профиля.
- dispatch-core.js — правила интерфейса; backend обязан отдельно проверять полномочия/состояние.
- provider.js — разделённые mock/API поставщики, без скрытого fallback.
- tests/interface/dispatch.test.cjs — проверка поведения provider и policy, не настоящий backend.

```powershell
node --test tests/interface/dispatch.test.cjs
```

Node требуется только для этих разработческих тестов; HTML и будущий Python сервер не требуют Node. Лия проверяет живой общий backend и D1–D10 отдельно.

## Роли и ветки

- Один QA.
- Два разработчика основы: бэкэнд/ядро и фронтэнд/интерфейс.
- Два full-stack разработчика функций; один из них использует Codex как помощника.
- Все участвуют в интеграции; одно конкретное слияние выполняет один выбранный оператор.

`main` хранит проверенную общую версию. Разработчики отправляют личные ветки и открывают PR. После готовности скелета фиксируем `beta-1` и создаём общую ветку функции `feature/beta1-f1`.

Одновременно пара основы делает `beta-2`, full-stack пара добавляет F1 к первой бете, QA проверяет основные функции снимка `beta-1`. Затем включаем актуальный main в ветку функции, проверяем совместный результат и объединяем его обратно в main через PR.

## Что сделать сегодня

Руководителю: пригласить четверых через **Settings → Collaborators → Add people**, заполнить роли и настроить защиту main по инструкции.

Каждому: принять приглашение, прочитать руководство, установить Git, клонировать проект, сделать маленький полезный PR с готовностью в своей строке таблицы участников.

~~~powershell
git clone https://github.com/Military05/Hackathon.git
cd Hackathon
git status
~~~

Полное готовое сообщение для отправки команде — раздел 14 [TEAM_WORKFLOW.md](TEAM_WORKFLOW.md).

## Что есть в структуре

`src/core` — правила и сценарии; `src/interface` — ввод/вывод; `src/features` — расширения; `src/storage` — хранение при необходимости. `tests` и `scripts` готовы для будущих проверок и команд. В каталогах пока только README с назначением.

Используйте стандартную структуру выбранного языка, если она удобнее. После получения задания заполните документы конкретными решениями и реализуйте один обязательный сценарий.

# Хакатон — мониторинг логистики предприятия

Если слово незнакомо, открой [словарь простыми словами](docs/GLOSSARY.md). Команды и названия полей не переводим: в коде они должны остаться точными.

**Выбрано задание №3.** Команда: один Лия (QA — тестировщик), разработчик бэкэнда, разработчик фронтэнда и два full-stack разработчика (каждый работает и с серверной частью, и с интерфейсом). План на два дня: 7–8 октября 2026, время Москвы; точные часы сверяем с регламентом.

Создаём мониторинг условного предприятия: транспорт, доступ в здания, состояние датчиков, журнал происшествий и карта. Собственная небольшая нейросеть ищет необычное поведение транспорта. Локальный ИИ-диспетчер запрашивает историю и объясняет происшествия.

**Сейчас опубликованы инструкции и структура. Код приложения, обучение нейросети и запуск локальной LLM (большая языковая модель) ещё не выполнены.** Команды Git уже применимы; команды приложения в RUNBOOK — целевой договор для реализации.

## Работа двух пар и Лия (QA — тестировщик)

Пара основы создаёт рабочий скелет → короткая проверка → тег beta-1.

После этого одновременно:

- пара основы улучшает main до beta-2;
- два full-stack в feature/beta1-f1 добавляют интеллектуальный анализ;
- Лия (QA — тестировщик) проверяет основные функции фиксированного снимка beta-1.

Затем main включается в ветку функции, Лия (QA — тестировщик) проверяет совместный SHA (идентификатор конкретной версии кода), итоговый PR (запрос на объединение изменений) попадает в main. Все помогают с интеграцией; одно конкретное слияние выполняет один выбранный оператор.

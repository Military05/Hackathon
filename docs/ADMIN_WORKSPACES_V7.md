# Рабочие места и администратор v7

Поручение координатора от 8 октября 2026. Этот документ заменяет старые правила
bootstrap, эскалации, резервного назначения и общего просмотра диспетчером.
Схема Event, история датчиков и наблюдения MLP сохраняются на сервере.

## Вход и доступ

При запуске сервер создаёт или приводит к новой конфигурации единственного
администратора: **admin / 123456768**. У admin нет dispatcher-профиля. Регистрация
создаёт только заявку диспетчера. Создание другого администратора запрещено.
При обновлении дополнительные старые admin-аккаунты становятся заблокированными
диспетчерами без назначенного профиля; их прежние записи аудита сохраняются.
Администратор назначает профиль и подтверждает заявку. Сохранение профиля
заблокированного пользователя сохраняет блокировку. Для доступа есть отдельная
кнопка «Разблокировать». Изменение доступа аннулирует прежние сессии пользователя.

| Роль | Область и действия |
| --- | --- |
| Диспетчер 1 | Логистика и склады, обработка своих происшествий |
| Диспетчер 2 | Производство, обработка своих происшествий |
| Диспетчер 3 | КПП и офис, проходы людей и свои происшествия |
| Администратор | Весь план, получатели происшествий, заявки и управление доступом |

Администратор может переключать демонстрационные сценарии и очищать список
карточек, но сервер запрещает ему принятие, реакцию, закрытие, передачу и прочие
действия диспетчера. Полномочия определяет серверная сессия; номер в URL их не меняет.
Пароли остаются PBKDF2-хешами, сессии — серверными, запросы записи защищены CSRF.

## Карточки и вкладки

«Транспорт и объекты» и «Люди» переключаются независимо; у них свои фильтры,
сортировка и прокрутка. Журнал КПП относится к вкладке людей. Чужие рабочие блоки
скрыты. Диспетчер получает случаи своего сектора и адресованные передачи;
администратор читает все случаи с указанием получателя.

Обработанные случаи скрыты по умолчанию. Список ограничен по размеру.
«Очистить происшествия» убирает карточки из текущей области просмотра: диспетчеру —
его доступные случаи, администратору — общий список. Это архивирование представления:
исходные Events, ModelObservation, история действий и материалы ИИ не удаляются.
Новые происшествия снова появляются. Детали занимают место только после выбора
карточки. Панели можно свернуть; ненужные для роли элементы скрываются.

Эскалация и автоматическое резервное назначение удалены. Согласованная передача
остаётся: владелец выбирает получателя, тот принимает адресованную передачу.

## Карта и демонстрация

Каждому диспетчеру соответствует один цвет объектов. Собственные объекты цветные,
чужие — серые; admin видит все три цвета. Красная и оранжевая маркировка зон
сохраняет смысл запрета и допуска. Ответственный за здание указан в подсказке,
а внутри здания остаётся короткое название.

«Показать на карте» включает сопровождение выбранного транспорта. Ручное
перемещение, «Мой сектор» и «Весь план» прекращают сопровождение. Возврат к общему
плану плавный; системное ограничение анимации учитывается.

Демонстрационные эпизоды въезда в красные/оранжевые зоны и аномального движения
передают настоящие синтетические position-события в общую SQLite. MLP читает эти
события штатным способом, без подмены ответов. Аномалии: возвраты туда-сюда,
повторные попытки ехать в стену и беспорядочная смена направления. Нарушающая часть сценария
ограничена во времени; затем продолжаются нормальные координаты и heartbeat,
чтобы не создавать потери связи при завершении эпизода.
[Все шесть новых эпизодов](MAP_SCENARIOS_V7.md).
Известные ложные срабатывания MLP на штатном движении не означают аварию.

Звук и его настройки убраны. История датчиков, технические данные и исходные
события не показываются в карточках, но сохраняются для MLP и инструментов агента.
Диагностика датчика остаётся ручной и периодической, с временем последнего сигнала.

## Запуск на другом устройстве

```powershell
git clone https://github.com/Military05/Hackathon.git
cd Hackathon
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

Откройте http://127.0.0.1:8000 и войдите admin / 123456768. Для подключённых
MLP/Qwen используйте Python 3.12 и [AI_CONNECTION](AI_CONNECTION.md).
Новый clone получает код и фиксированный bootstrap admin; чужие диспетчеры,
их пароли и журналы не копируются из Git. Для общих аккаунтов с разных ноутбуков
все открывают один сервер по [REMOTE_CLIENT_V6](REMOTE_CLIENT_V6.md).
Разным аккаунтам в одной комнате нужны отдельные профили браузера/устройства.

Работа выполнялась в отдельных ветках Егора С./М. Модули владельцев ML/ИИ не
переписывались. По прямой просьбе координатора тесты этой поставки не запускаются.

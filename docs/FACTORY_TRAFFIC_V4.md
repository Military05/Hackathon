# Движение транспорта на автомобильном заводе

7 октября 2026. В версии карты v3 транспорт не двигался, потому что в базовой
поставке ещё не было работающего источника `position`: интерфейс показывал
последние фактически полученные координаты. Теперь сервер содержит небольшой
демонстрационный источник `src/core/demo_traffic.py`. Он запускает обычную работу
завода при старте сервера и записывает настоящие демонстрационные Event в общую
SQLite через `Service.ingest_event`. Все диспетчеры получают одни и те же данные.

Это синтетическое демо с `demo=true`, а не подключение физических машин или
датчиков. Исходники отдельного симулятора, ML и ИИ-агента не изменялись.

## Как проверить

1. Обновите `main`, установите существующие зависимости и запустите
   `powershell -ExecutionPolicy Bypass -File scripts/start.ps1`.
2. Откройте интерфейс и убедитесь, что статус сценария показывает обычную работу,
   число событий растёт, а три машины меняют положение. Краткая остановка на
   маршруте — нормальная демонстрационная погрузка/ожидание.
3. Выберите сценарий в панели демонстрации и нажмите «Запустить сценарий».
   Это переключает один общий источник для всех окон; новый запуск начинает
   эпизод с его исходных позиций. История предыдущих событий сохраняется.
4. Для происшествия откройте карточку и нажмите «Показать на карте». Выбор карточки
   сам не перемещает карту. Принятие и реакцию проверяйте в разных профилях.
5. Нажмите «Остановить». Новые позиции и heartbeat прекращаются. Последние точки
   остаются на карте, спустя demo-порог 5 секунд становятся устаревшими и правила
   фиксируют потерю источников. Ручная проверка датчиков читает это состояние и
   сама не восстанавливает связь. Новый обычный сценарий возвращает свежие Events.

Для независимой чистой проверки используйте новый файл, сохраняя прежнюю базу:

```powershell
$env:DISPATCH_DB='data/runtime/factory-v4-qa.db'
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

## Сценарии

| `scenario` | Что происходит |
| --- | --- |
| `normal` | Три машины движутся по своим дорожным петлям и кратко останавливаются возле заданного назначения. Нарушений по сценарию нет. |
| `logistics` | Погрузчик складского сектора движется быстрее, погрузочные остановки увеличены до 6 секунд; остальные машины продолжают движение. |
| `shift` | Служебная машина чаще движется по общему маршруту; сотрудник U3 с допуском проходит в главный офис и выходит. Нарушения доступа нет. |
| `service` | Изменяются скорость объезда и длительность остановок технической службы; телеметрия продолжается. |
| `forbidden-zone` | V1 по соединённому погрузочному подъезду въезжает в Z1, останавливается на 8 секунд и возвращается на общий маршрут. Правило реально создаёт `forbidden_zone`; две свежие точки снаружи подтверждают восстановление. |
| `unauthorized-access` | На 6-й секунде датчик ACCESS-O1 сообщает один подтверждённый проход U1 в офис без допуска, на 13-й — выход. Создаётся один разовый случай `unauthorized_access`. |
| `sensor-offline` | HB-QA действительно перестаёт посылать Events с 5-й до 17-й секунды. После порога создаётся `sensor_offline`, возврат heartbeat восстанавливает условие. Транспорт продолжает движение. |
| `simultaneous` | Объединяет въезд V1 в Z1, проход U1 без допуска и потерю HB-QA. Все три типа правил работают одновременно. |

Нарушения доступа/зоны/связи происходят один раз на запуск сценария. После этого
движение продолжается без бесконечного создания одинаковых учебных тревог.
Сценариев с выдуманной оценкой нейросети нет; ML и анализ ИИ доступны только после
фактического подключения модулей их владельцев.

## Маршруты и нагрузка

Схема v4 использует `site.routes.V1/V2/V3`, а нарушения зоны —
`site.demo_fault_routes.V1`. Нормальное движение идёт по длине дорожной линии с
постоянной скоростью между остановками. Разное число точек на скруглениях не
изменяет скорость; координаты считаются из прошедшего времени, поэтому ошибка
не накапливается на каждом обновлении. Отдельный тест проверяет непрерывность
возврата с погрузочного подъезда на дорожный маршрут.

Источники обновляются раз в секунду: три position и два heartbeat, обычно пять
Events/с; событие прохода добавляет одну запись в выбранный момент. Дополнительных
процессов, Docker, GPU или модели для движения не требуется. Сервер пропускает
опоздавший кадр и не выдаёт догоняющую пачку. В памяти хранятся текущие маршруты,
состояние трёх машин и два флага прохода; история Events остаётся в SQLite. При
долгой непрерывной работе файл истории растёт — для каждого нового учебного
прогона можно назначать отдельную базу.

Это не измерение производительности целевого ноутбука. Его проверяет Лия с тремя
одновременными клиентами и фактически подключёнными ML/ИИ.

## Интеграция второго контроллера

При `DISPATCH_ENABLE_SIMULATOR=1` сервер сначала подключает переданный владельцем
`src.simulator.run.DemoRunner`. Если модуль отсутствует или отключён, работает
встроенный источник; два источника одновременно не запускаются. Включение
внешнего источника выполняется после согласования новой геометрии завода.

```powershell
# Без автоматического старта, управление кнопками остаётся доступным:
$env:DEMO_AUTOSTART='0'

# Отключить встроенное движение для ручных Event/интеграционных проверок:
$env:DISPATCH_ENABLE_DEMO_TRAFFIC='0'

# Включить только фактически переданный внешний симулятор:
$env:DISPATCH_ENABLE_SIMULATOR='1'
```

`GET /api/demo/status` показывает `source=builtin_factory_traffic`,
`running`, `scenario`, `event_count`/`events_sent`, `elapsed_seconds`,
`vehicle_states` и список сценариев. `POST /api/demo/start` и
`POST /api/demo/stop` сохраняют прежний контракт и проверку профиля диспетчера.
Переключение выполняется последовательно под одним серверным lock. Stop ждёт
окончания выполняющегося кадра, поэтому после его ответа от старого запуска
не придут запоздалые Events. Ошибка первого кадра возвращает 503 вместо
успешного ответа о якобы работающем движении.

## Проверки поставки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests/runtime -p 'test_demo_traffic.py' -v
.\.venv\Scripts\python.exe -m unittest discover -s tests/runtime -p 'test_extensions.py' -v
```

Проверяются длина маршрута, отсутствие накопленной ошибки, остановки, настоящие
Events и свежесть источников, непрерывность движения, один эпизод зоны и его
восстановление, подтверждённый проход, действительная пауза heartbeat,
одновременные правила, единственный активный источник, отсутствие Events после
stop и честная ошибка первого кадра. Итоговые результаты общего прогона
фиксирует интегратор вместе с SHA выпуска.

Общий прогон собранной версии v4: 56 runtime-тестов, 18 QA-тестов и 59
интерфейсных тестов — PASS. В Chrome на работающем сервере проверены общее
движение двух рабочих мест, переключение сценариев, въезд и выход из Z1,
принятие случая и запись реакции, реальная пауза heartbeat и восстановление,
ручная диагностика без подмены сигнала, остановка и повторный запуск.
Страница при 1366×768 не имеет горизонтального переполнения; подписи остаются
внутри зданий. Измерения на целевых ноутбуках и общий прогон с ML/ИИ — NOT RUN.

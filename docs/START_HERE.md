# Начало работы — новая цель v2

Сначала открой [план](TASK_03_PLAN.md), [три диспетчера](DISPATCH_OPERATIONS.md), [контракт](CONTRACTS.md) и [свою роль](TEAM.md). Передача, напоминания и эскалация обязательны; приложение ещё предстоит реализовать.

## Первые действия каждого

1. Принять приглашение GitHub. Открыть Military05/Hackathon → Code → HTTPS и скопировать адрес.
2. Открыть PowerShell, проверить git --version и python --version (Python 3.11+). В своей рабочей папке выполнить команды ниже. Если клон уже есть, не клонировать поверх него: перейти в него и проверить git status.

```powershell
git clone https://github.com/Military05/Hackathon.git
cd Hackathon
git status
git remote -v
```

3. VS Code → Файл → Открыть папку → этот клон; Терминал → Создать терминал. Команды запуска выполняются из корня клона.
4. На GitHub открыть docs/TEAM.md и свою инструкцию; записать GitHub-ник через отдельный PR, если ещё не указан. Личные имя/email Git задавать своими.
5. Issues → New issue → «Задача команды»: взять свой следующий T-ID из BACKLOG, указать разрешённые файлы/зависимость/expected. Не создавать одинаковую задачу повторно.
6. Получить свежий main и создать личную ветку согласно роли. Прототип агента до beta-1 — prototype/agent-runtime. Незаконченный код не отправлять прямо в main.

## Что согласовать в первые 30 минут

Егор С. фиксирует site.json: buildings/zones/assets/sensors/permissions/site_areas/sectors/operator_profiles/dispatch_config. Егор М. подтверждает три профиля и JSON; Гриша — совпадающие ID/сценарии; Гаджи — query provider, snapshot, jobs; Лия — D1–D10 и конкурентную приёмку.

Назначение участков и эскалации не делает LLM. Header X-Demo-Operator выбирает demo-профиль, не пароль. Один Incident может иметь много уведомлений и только одного assigned_operator_id; несколько разных Incident независимы.

## Что можно делать без ожидания другого

| Участник | Сразу начинает | Для интеграции ждёт |
| --- | --- | --- |
| Егор С. | события/схема/правила/атомарные операции | интерфейсы подключения ML/агента |
| Егор М. | SVG и компоненты на fixtures | API v2 от Егора С. |
| Гаджи | Bionic Local → API → настоящий tool call, registry/loop на fixtures | query/storage от Егора С., UI от Егора М. |
| Гриша | normal/D1–D10 fixtures и генерация/обучение | приём API, подключение inference |
| Лия | таблица кейсов, QA-конфиг, гонки/границы | опубликованный SHA и команда автора |

Блокировку сообщить в общий чат: «T-ID; что не работает; нужный человек; ожидаемый интерфейс; следующий шаг». Не останавливать независимую работу и не переписывать чужой модуль без согласования.

## Передача изменений

Проверить свой результат → git status → git add конкретные файлы → git diff --cached → commit → push → Pull requests → New pull request. Для основы base=main; для ML/агента после beta-1 base=feature/beta1-f1. Подробные команды есть в роли и TEAM_WORKFLOW.

Автор передаёт полный SHA, запуск, вход и ожидаемое поведение. Лия проверяет фиксированный снимок; после изменения кода результат обновляется. beta-1/beta-2/финальный tag ставят по работающей версии, не заранее.

За 3 часа до сдачи — никаких новых требований. Все D1–D10 и offline прогон остаются обязательными; невыполненное честно записывается в RELEASE. [RUNBOOK](RUNBOOK.md), [TESTING](TESTING.md).

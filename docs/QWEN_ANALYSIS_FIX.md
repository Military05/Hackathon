# Исправление анализа Qwen

Ветка: `codex/fix-qwen-analysis-failures`.

## Причина

Рабочая SQLite прочитана через URI `mode=ro` с `PRAGMA query_only=ON`.
Последний сбой: `aj-496646aef3cb4a38a3cb47a81db620c8`, происшествие
`incident-7885686be944446aa1fe87b865405b05`.
Сохранённая ошибка: `not_found`, `Incident is outside the captured scope.`
Она возникает только при вызове моделью `get_incident` с ID, отличающимся
от ID замороженного снимка. Общая схема инструмента разрешала любой ID.
Проверка области доступа правильно отклонила запрос. Признак `stale`
вычисляется отдельно при опросе и не был причиной этого отказа.
Ранее в журнале встречались `invalid_evidence`, HTTP 400 и неверный JSON;
это отдельные ошибки, а не доказательство одной общей причины всех отказов.

## Изменение

Схемы инструментов ограничены точными ID происшествия, объектов и датчиков
из снимка. Инструменты для отсутствующих ресурсов не предлагаются.
Проверка аргументов и достоверности результата остаётся независимой и строгой;
чужие ID не подменяются правильными. Версия запроса повышена для нового ключа кеша.
Ошибки интерфейса объясняют отказ и возможность повтора без технического JSON.
Изменение данных показано отдельно от причины ошибки; завершённый старый
результат по-прежнему помечается устаревшим.

## Безопасное обновление ноутбука

1. Не выполняйте pull/switch в работающем checkout. Получите ветку и создайте
   отдельный worktree; сравните полный SHA с SHA PR.

   ```powershell
   git fetch origin codex/fix-qwen-analysis-failures
   git worktree add --detach .worktrees/qwen-analysis-release origin/codex/fix-qwen-analysis-failures
   git -C .worktrees/qwen-analysis-release rev-parse HEAD
   ```

2. Проверьте новую копию на временной SQLite и отдельном порту. Используйте
   установленный Python и существующий Qwen API. Рабочую базу не используйте
   для пробного запуска; не создавайте в ней аккаунты и не очищайте журнал.
3. После проверки владелец выбирает окно обслуживания, делает согласованную
   резервную копию SQLite и переключает только backend на новый checkout.
   Сохраните прежний абсолютный `DISPATCH_DB`, настройки авторизации,
   source key и параметры Qwen. Не запускайте второй backend на рабочей базе.
   Не перезапускайте модель и не переустанавливайте веса.
4. После переключения проверьте health, вход, анализ и повтор в интерфейсе.
   Старые ошибки останутся в истории; новый запрос использует новую версию.
   Для отката верните прежний checkout и те же настройки/базу.

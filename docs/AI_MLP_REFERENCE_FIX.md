# Точное подтверждение MLP без копирования чисел языковой моделью

Ветка `codex/fix-mlp-integral-score`, исходный SHA
`4cfe210578c5c7454ca5390c12585ad3b8004623`.

В резервной копии конкретное неуспешное model_anomaly содержит score=1.0.
Ошибка: `Fact ID/field/value was not returned by an executed tool.`
JSON Schema считает 1 и 1.0 эквивалентными числами; локальный structured-output
может вернуть 1, тогда как строгий валидатор сравнивает точные JSON-значения.
Обычный тест с дробным score не закрывал этот случай.

Теперь для model_anomaly Qwen выбирает `reference_facts`: source, id, field,
без value. Это отдельный протокол ссылок, а не исправление присланных чисел.
Разрешены ровно status, score, threshold связанной observation_id.
Сначала строго проверяются формат, связанное наблюдение и полнота ссылок;
значения извлекаются из записей выполненных tools. Затем прежний строгий
валидатор проверяет факты и наличие всех событий наблюдения. Источник числа
и ссылки Qwen сохраняются в technical. Старые числовые ответы также продолжают
проверяться строго: 1 не подменяется на 1.0 и не принимается вместо него.

Публичная форма verified facts не изменилась. Версия инструкции новая,
поэтому старые результаты не переиспользуются как ответы нового протокола.

Проверки на отдельной временной базе:

```powershell
python -m pytest tests/agent tests/ml -q --basetemp=tmp/reference-tests
python -m unittest discover -s tests/runtime -p 'test_ai_integration.py' -q
```

140 AI/ML-тестов и 13 интеграционных AI-тестов: PASS.
Регрессии проверяют score=1.0, чужую observation_id, повторение поля,
добавление чисел в ссылку, непрочитанные наблюдения и отсутствующие события.
Тот самый сохранённый неуспешный MLP-снимок повторён с настоящей Qwen через
локальный LM Studio: PASS, float 1.0 сохранён, три ссылки проверены.
Исходная резервная копия и рабочая база не изменялись.

Статус «УСТАРЕЛ» не отключён. Новые координаты/наблюдения и изменение
происшествия могут сделать результат анализа прежнего состояния устаревшим.
Само течение времени без новых данных не должно менять snapshot_id;
соответствующие интеграционные тесты проходят.

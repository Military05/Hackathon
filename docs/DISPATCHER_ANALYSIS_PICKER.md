# Выбор происшествия для анализа

Ветка: `codex/dispatcher-scoped-analysis`.
Исходный `origin/main`: `5ba4411946eb7e77fa9db0e1b42a8e2bb9a876cc`.

Новый список связан с аккаунтом текущего диспетчера, а не с выбираемым
пользователем сектором. Он показывает активные случаи текущей вкладки:
неназначенные случаи своего сектора, принятые этим диспетчером и адресованные
ему передачи. Это соответствует `Service._visible_to`; серверная проверка
сессии, CSRF и области ответственности сохранена. Администратор список не видит.
Список ограничен загруженными сервером 200 записями рабочего места.

Перед отправкой запроса интерфейс повторно проверяет область ответственности
по последней загруженной карточке. Изменение ответственности после этой проверки
по-прежнему отклоняет сервер. Получатели передачи не ограничены своим сектором:
межсекторная адресованная передача остаётся доступной.

Отсутствие объекта в ответе `/assets` больше не означает, что он не зарегистрирован.
Карточка проверяет справочник `/site`: при отсутствии телеметрии сообщает об
неизвестном текущем месте, не подставляя координаты справочника. Если записи нет
и в справочнике, сообщает об этом отдельно. Существующие происшествия остаются
доступны через ссылки карточки. Сообщения сервера о чужом секторе и исчезнувшем
происшествии переведены в понятные инструкции диспетчеру.

Изменяются только `app.js`, `index.html`, тесты интерфейса и этот документ.
SQLite, сервер запуска, модели и правила не изменяются.


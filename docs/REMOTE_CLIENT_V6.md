# Другой ноутбук: тот же сервер или новая отдельная установка

Инструкция для базового продукта с серверными аккаунтами. Основа проверки:
`be305a359099088dcb9cd440629b2e0913e63dbc`; удалённое TLS-подключение на реальных
устройствах здесь не выполнялось. ML/ИИ подключаются отдельно по
[AI_INTEGRATION_V6](AI_INTEGRATION_V6.md).

## 1. Чтобы сохранить общие аккаунты и события, открывайте тот же сервер

На первом компьютере работают Python/FastAPI и одна SQLite. На втором нужен
браузер: карту, сценарий, аккаунты и журнал он получает с первого компьютера.
Клонировать Git, ставить Python или запускать модель на клиентском ноутбуке
для этого не нужно. Входите аккаунтом, который уже подтверждён на этом сервере.

Аккаунты, хеши паролей и сессии находятся в SQLite, обычно
`data/runtime/dispatch.db`, либо в пути DISPATCH_DB. Они не хранятся в Git и не
появляются на другом сервере после `git pull`. Рабочая база сохраняется после
перезапуска; заново создавать администратора каждый раз не нужно.

Адрес `127.0.0.1` всегда означает компьютер, на котором открыт браузер. На втором
ноутбуке `http://127.0.0.1:8000` не обращается к первому. Нужен адрес/имя общего
сервера, например `https://имя-сервера:8000`, соответствующий его сертификату.
Три разных аккаунта открывают в отдельных профилях браузера, разных браузерах
или на разных компьютерах: обычные вкладки одного профиля разделяют cookie.
Изменение `?operator=dispatcher-2` не меняет роль вошедшего пользователя.

## 2. Подготовка общего сервера владельцем

Сохраните существующий DISPATCH_DB. Если администратор уже создан в этой базе,
пропустите bootstrap. Для первой пустой установки он выполняется локально:

```powershell
.\.venv\Scripts\python.exe scripts/manage_users.py create-admin
```

Введите собственные данные; готового admin/admin нет. В этой базовой версии
пароль допускает 8–128 символов и хранится как PBKDF2-хеш со случайной солью.
Новые заявки подтверждаются в «Администрировании» с назначением профиля:
1 — логистика/склады, 2 — производство, 3 — КПП.

Владелец заранее предоставляет сертификат и приватный ключ, а браузеры клиентов
доверяют этому сертификату/его издателю. Сертификат должен содержать действительное
имя/IP общего сервера. Штатный запуск:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Lan -Port 8000 -TlsCert 'E:\certs\factory.crt' -TlsKey 'E:\certs\factory.key'
```

Скрипт использует один worker, HTTPS и --no-proxy-headers. Он не создаёт сертификат,
не устанавливает доверие в браузерах, не открывает Windows Firewall и не изменяет
маршрутизатор. Эти сетевые настройки владелец проверяет отдельно. Приватный ключ
не помещается в Git или web-каталог. Нельзя принимать отключение проверки
сертификата за успешный защищённый доступ.

Обычный удалённый HTTP для входа/API отклоняется. Альтернатива TLS — отдельно
проверенный шифрующий VPN/туннель, через который идут все клиентские подключения.
После проверки владелец может задать DISPATCH_TRUST_ENCRYPTED_TUNNEL=1. Эта
переменная не устанавливает туннель и сама ничего не шифрует; обычный порт не
должен оставаться доступным из незашифрованных сетей. Публичный проброс порта
приложения в этой поставке не выполняется.

Если уезжаете в другой город, ноутбук-сервер должен оставаться включённым,
не уходить в сон и сохранять подключение к сети. Нужна заранее проверенная
доступность через защищённую сеть: работоспособность в одной комнате её не
доказывает. Устройство клиента не берёт на себя серверную нагрузку модели.

## 3. Проверка на втором ноутбуке

1. Откройте HTTPS-адрес общего сервера. Не должно быть ошибки доверия сертификату.
2. Войдите уже существующим подтверждённым аккаунтом. Если это новая заявка,
   администратор подтверждает её на том же сервере.
3. Проверьте назначенный сектор, движение, свежесть датчиков и журнал КПП.
4. Оба клиента должны видеть один выбранный сценарий и те же события/действия.
   Проверьте это по одному конкретному ID события или происшествия.
5. Выйдите на клиенте; его сессия отзывается. Для демонстрации разных профилей
   используйте отдельные браузерные профили, не последовательные входы в обычных
   вкладках. При смене cookie старая вкладка получает session_identity_changed.

Если страница не открывается, сначала проверяют работающий сервер, верный адрес,
защищённую сеть, порт и доверие сертификату. Ошибка связи не исправляется
повторной регистрацией в другой базе. Если вход не принят, администратор проверяет
активность аккаунта на общем сервере, не ищет пароль в Git.

## 4. Когда на втором ноутбуке всё-таки нужен clone

Clone нужен для разработки или отдельного самостоятельного сервера. Новый сервер
с новой SQLite не знает аккаунты старого: создайте собственного администратора,
подтвердите собственные заявки. Его сценарии/журнал независимы, даже если код
полностью одинаковый. Это две установки, а не два окна одного предприятия.

```powershell
git clone https://github.com/Military05/Hackathon.git
cd Hackathon
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
.\.venv\Scripts\python.exe scripts/manage_users.py create-admin
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

Если требуется перенести сам общий сервер с сохранением истории, координатор
отдельно организует перенос рабочей SQLite после остановки сервера и резервной
копии. Не коммитьте базу с аккаунтами в Git, не копируйте работающую SQLite как
случайный файл и не объединяйте два независимых журнала автоматически. Для
обычного удалённого рабочего места перенос базы не требуется.

## 5. Нагрузка и границы проверки

Базовый режим: один worker, SQLite, встроенные источники раз в секунду; браузер
получает данные и рисует карту. Для клиента GPU не требуется. Общий ноутбук с
32 ГБ памяти предпочтительнее для сервера и возможной модели; фактическую
скорость с тремя клиентами и LLM проверяет Лия. Наличие свободной RAM/VRAM само
по себе не является результатом такой проверки.

Большая модель остаётся на выбранном сервере/runtime, не копируется на каждый
клиент и не скачивается вследствие входа или clone. Работа базового приложения
не подтверждает, что ИИ поставлен и доступен. Доверенный TLS, другой город,
переподключение и целевые ноутбуки — NOT RUN в подготовке этого документа.

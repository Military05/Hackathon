# Ограниченный snapshot накопленного MLP-происшествия

Ветка: `codex/fix-agent-snapshot-evidence-limit`.
Исходный актуальный `origin/main`: `7b2e9849e6b123d518c697c9acbf3849d4b0cc76`.
Работа выполнялась в отдельном worktree. Основные рабочие копии, процесс сервера,
производственные настройки, SQLite и аккаунты не изменялись.

## Причина и исправление

`Service._evidence()` сохраняет первое событие и последние 99 подтверждений.
После восстановления связанная аномальная оценка остаётся исторической, а
последняя нормальная оценка содержит новые события. Раньше `capture_snapshot()`
объединял все ссылки и отклонял объединение свыше 100 до постановки задания.

Лимиты **100 событий / 256000 байт** остаются прежними. Если объединение
помещается, сохраняется прежний отбор. При переполнении:

1. Все доказательства связанной оценки сохраняются целиком, без изменения оценки.
2. По возможности сохраняются первое подтверждение и свежая позиция каждого объекта.
   Для парного происшествия учитывается начальное подтверждение каждой машины.
3. Последняя дополнительная оценка включается только целиком с её доказательствами.
   Если она не помещается, исключается вся оценка, а не отдельные ссылки внутри неё.
4. Остаток заполняется последними подтверждениями происшествия, затем измерениями.
   Сортировка детерминирована временем и event_id.
5. Только detached-копия `Incident.evidence_event_ids` сокращается до включённых ID.
   SQLite, исходные Incident, Events, ModelObservation и журналы не записываются.

Все исходные обязательные ссылки проверяются **до** отбора: отсутствие события,
конфликт ID, неверный объект оценки/доказательства, повторные/неверные ID и
некорректное время не скрываются усечением. `FrozenSnapshot` дополнительно
требует наличия всех ссылок каждой включённой оценки и соответствия её объекту.
`get_incident` действительно возвращает необходимые события обеих оценок;
при сокращении также возвращает сохранённые свежие позиции. Валидатор принимает
только прочитанные ID/поля/точные значения; отсутствующие события не восстанавливает.

Ни одна отдельная оценка с доказательствами свыше лимита не сокращается для
получения положительного результата: такой некорректный вход отклоняется.
Если полное доказательство связанной оценки заняло весь лимит, свежие измерения
могут не поместиться; это явно отмечается, текущее положение не заявляется.

## Совместимое расширение

При переполнении `history_bounds.evidence_selection` содержит:
`version`, `partial`, `original_incident_count`, `required_union_count`,
`selected_event_count`, `omitted_incident_count`, `omitted_observation_ids`,
`first_incident_event_included`, `fresh_measurements_included`, `source_digest`.
Это метаданные отбора, не дополнительные события или доказательства выводов.
Digest охватывает исходный список ID и исходные оценки, включая исключённые,
поэтому изменения за пределами выбранных событий также влияют на snapshot_id.
Метаданные доступны tools и сохранены в техническом отчёте; обычная карточка
объясняет, что использована часть сохранённой истории. `get_event_history`
указывает truncated при таком срезе. Event/ModelObservation JSON и SQLite-схема
не меняются. Общие ID, кэш и stale проверяются прежними механизмами.

Prompt version обновлена до `dispatcher-v7-bounded-evidence-v5`.
Живой тест выявил независимую ошибку генерации: прежняя схема разрешала
комбинировать score и threshold с любым из их значений. Добавлен enum **полных
проверенных утверждений**, связывающий поле с его точным значением. Валидатор
не ослаблен и не исправляет ответы Qwen; ошибочный ответ по-прежнему отклоняется.

Ошибки отправки запроса выводятся непосредственно в области анализа, сохраняются
после polling и сбрасываются при выборе другой карточки/успешном запросе.
Не показываются внутренний JSON, исходные технические сообщения и ложный статус
завершения; дизайн и расположение элементов сохраняются.

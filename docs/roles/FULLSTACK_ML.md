# Гриша (B2) — full-stack: симулятор и собственная нейросеть

Ты создаёшь показания модельного предприятия, обучаешь небольшую нейросеть и подключаешь её результат к приложению. Full-stack означает работу с логикой и интерфейсом своей функции.

MLPClassifier — нейросеть из готовой библиотеки. Вы создаёте данные и обучаете её веса; это собственное обучение небольшой модели, а не разработка большой языковой модели с нуля.

[План](../TASK_03_PLAN.md), [форматы и признаки](../CONTRACTS.md), [архитектура](../ARCHITECTURE.md), [запуск](../RUNBOOK.md), [словарь](../GLOSSARY.md).

## Что делать до beta-1

1. Согласуй с Егором С. (A1) `site.json` и формат события.
2. Создай normal simulator (симулятор обычного движения): позиции и heartbeat — сообщение датчика «я работаю».
3. Подготовь D1 (запрещённая зона), D2 (проход без допуска), D3 (потеря связи) и возвращение к норме.
4. Дай Егору С. (A1) / Егору М. (A2) события для первого реального запуска.
5. Согласуй movement-v1 — семь числовых признаков движения, окно 10 секунд, шаг 5 секунд.
6. Начни подготовку независимых эпизодов для обучения.

Не жди агента Гаджи (B1): генерация данных и нейросеть работают отдельно.

## Твои файлы

`src/simulator/`, `src/ml/`, `tests/ml/`, тестовые данные по договорённости с Лией (QA — тестировщик). Интерфейс оценки согласуй с Егором М. (A2), общие маршруты сервера — с Егором С. (A1).

Простой симулятор нужен уже первой версии; отправь его ранним запросом в main. Нейросеть добавляй затем через общую ветку функции.

## Подготовка данных

Эпизод — законченный отрезок движения с идентификатором, параметрами и меткой «обычный» или «необычный».

Seed — начальное число генератора, позволяющее повторить те же данные. Меняй seed и параметры между обучающими и независимыми проверочными эпизодами.

Обычные эпизоды: разные допустимые маршруты, темп, остановки. Необычные: необычные сочетания остановок и изменений движения. Не выбирай задачу, которую уже полностью решает правило попадания в запрещённую зону.

В модель не передавай название сценария, правильный класс, готовое нарушение или идентификатор, выдающий ответ. Признаки вычисляй только по исходной истории позиций.

## Как обучать

- Один extractor (функция вычисления признаков) для обучения и приложения.
- Разделение по целым эпизодам: train (обучение), validation (выбор настроек), test (итоговая независимая проверка).
- Окна одного эпизода не попадают в разные части.
- StandardScaler (масштабирование числовых признаков) обучается только на train.
- Pipeline (сохранённая цепочка обработки): scaler → MLPClassifier, слои 16 и 8, `random_state=42`.
- Threshold (порог тревоги) выбирается на validation.
- Для score (оценки модели) выбирай столбец класса anomaly (необычное движение), а не произвольный.
- Зафиксируй `max_iter` и предупреждения о незавершённом обучении.
- Сохрани модель, версии, порог, порядок классов и параметры данных.
- Итоговый test не используй для подбора. Если уже использовал, нужен новый независимый test.

Количество данных само по себе не доказывает качество.

## Как оценивать результат

Заполни [ML_REPORT](../ML_REPORT.md) реальными числами:
- сколько эпизодов в каждой части;
- версии и seed;
- confusion matrix (таблица верных и ошибочных ответов);
- precision (доля правильных тревог), recall (доля найденных аномалий), F1 (общая оценка этих двух показателей);
- ложные тревоги, пропуски, время вычисления;
- сравнение с baseline (простым алгоритмом).

Здесь F1 — метрика модели. В названии ветки F1 — первая дополнительная функция: это два разных обозначения.

Если простой алгоритм лучше нейросети, запиши честный результат. Не обещай заранее 100% точности.

## Подключение в приложение

Inference — применение уже обученной модели к новым данным. Загрузи модель один раз; не обучай её внутри запроса сервера.

Окно 10 секунд, шаг 5, минимум 6 позиций. Мало данных — `insufficient_data` («недостаточно данных»), без выдуманной оценки.

Результат ModelObservation содержит версии и ссылки на исходные события. Оценка модели не равна доказанной вероятности аварии. Перекрывающиеся окна не создают поток одинаковых происшествий: жизненный цикл определён в CONTRACTS.

D4 — отдельный эпизод необычного движения для проверки модели.

## Ветки

Для раннего симулятора:

~~~powershell
git switch main
git pull --ff-only origin main
git switch -c core/demo-simulator
~~~

После проверки отправляй PR (запрос на объединение) в main.

После создания Гаджи (B1) общей ветки:

~~~powershell
git fetch origin
git switch -c feature/f1-ml origin/feature/beta1-f1
~~~

Это твоя личная ветка нейросети. Для отправки:
1. Проверь результат.
2. `git add путь-к-файлу` — подготовь конкретные файлы.
3. `git diff --cached` — просмотри.
4. Сохрани и отправь:

~~~powershell
git commit -m "Добавить обучение и оценку модели движения"
git push -u origin feature/f1-ml
~~~

5. Создай PR с `base=feature/beta1-f1`. Для раннего симулятора имя ветки и назначение другие — смотри выше.
6. Передай Лие (QA — тестировщик) команды и фактический отчёт.

[Полная Git-инструкция](../../TEAM_WORKFLOW.md).

## Передача и готовность

Проверь повторяемость seed, непересечение эпизодов, одинаковые признаки при обучении/запуске, отсутствие модели, ложные тревоги и D4 на независимых данных.

Лия (QA — тестировщик) получает команды генерации/обучения/оценки, отчёт, версию кода SHA (`git rev-parse HEAD`) и ожидаемый результат. Готовность подтверждается сохранённой обученной моделью и повторением другим участником; шаблон отчёта сам по себе ничего не подтверждает.

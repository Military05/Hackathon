# B2 — full-stack разработчик симулятора и нейросети

## Твой результат

Воспроизводимые события предприятия, обученная вами небольшая нейросеть, отчёт её качества и подключение результатов к общей системе.

Используем MLPClassifier: это нейросеть на готовой библиотеке, обученная на вашем датасете. Не заявляем собственную фундаментальную LLM или доказанную пригодность для настоящего завода.

Читать: [план](../TASK_03_PLAN.md), [контракты](../CONTRACTS.md), [архитектуру](../ARCHITECTURE.md), [RUNBOOK](../RUNBOOK.md).

## До beta-1

1. С A1 согласуй site.json и Event v1.
2. Сделай небольшой normal simulator: позиции транспорта и heartbeat.
3. Подготовь D1/D2/D3 и отдельный сценарий возврата к норме.
4. Отдай A1/A2 последовательности для реального первого запуска.
5. Согласуй семь признаков movement-v1 и окно 10 секунд/шаг 5 секунд.
6. Начни генератор независимых эпизодов для обучения, пока ждёте готовность скелета.

Не жди локальную LLM B1. Твои данные, обучение и inference работают независимо от неё.

## Как генерировать данные

Каждый эпизод имеет episode_id, seed, scenario, список сырых событий и независимую метку normal/anomaly.

Normal — движение по разным разрешённым маршрутам с вариациями темпа и остановок. Anomaly — необычные сочетания остановок и изменений движения. Выбери сценарий, который обычная проверка зоны/допуска не решает автоматически.

В нейросеть не передаём scenario name, label, forbidden flag, готовый incident type или id, который кодирует класс. Метка описывает сценарий генерации, а признаки вычисляются только из raw position history.

Обучающие эпизоды и демонстрационные/тестовые эпизоды различаются seed и параметрами. Не разрезаем один длинный эпизод на окна, случайно распределённые между train/test.

## Обучение

- Один общий feature extractor используется в offline training и online inference.
- Признаки и единицы строго из CONTRACTS.
- Split по episode_id: train, validation, final test.
- StandardScaler обучается только на train.
- Pipeline: scaler → MLPClassifier(hidden_layer_sizes=(16,8), random_state=42).
- Порог выбирается по validation и сохраняется.
- Фиксируем class order: положительный класс anomaly; не берём произвольный столбец predict_proba.
- max_iter и контроль convergence выбираем разумно; warning о недообучении не скрываем.
- Сохраняем model pipeline + metadata + report.
- Test используем один раз для итоговой оценки; если подбирали на нём параметры, нужен новый независимый test.

Для первого эксперимента достаточно небольшого датасета на CPU. Объём не выдаёт качество: смотри результат на независимых эпизодах.

## Отчёт

Сохрани docs/ML_REPORT.md с фактическими числами: episodes по split, генерация/seed, feature_version, модель, threshold, confusion matrix, precision/recall/F1, false positives, inference time.

Сравни с простым baseline на тех же split. Если MLP хуже, это честный результат и отдельная задача, а не причина скрывать baseline.

## Inference

Окно 10 секунд, шаг 5, минимум 6 samples. Иначе insufficient_data, без score. Загруженная модель возвращает ModelObservation и список исходных event ids.

Не обучай модель внутри HTTP handler. Артефакт загружается один раз. score отражает выход вашей модели на этой задаче, не вероятность аварии.

Необычное окно может создавать incident model_anomaly; разные перекрывающиеся окна одного эпизода не должны засыпать интерфейс дубликатами. Согласуй cooldown/active incident с A1 и зафиксируй параметр.

## Самопроверка и передача

- Один seed повторяет raw сценарий.
- Точные D1–D3 работают без модели.
- Train/test episode ids не пересекаются.
- Offline/online extractor даёт одинаковые features.
- Отсутствующий артефакт виден как not_trained.
- На normal тестах измерены ложные тревоги.
- D4 на отдельном demo эпизоде виден на карте, если модель его обнаружила.
- ModelObservation содержит версию и evidence.

QA получает команды генерации/обучения/evaluation, report, проверенный SHA, expected ids и новый независимый сценарий. Не обещай заранее 100% accuracy.

## Готово, когда

Артефакт обучен вами, данные воспроизводимы, метрики фактические, inference подключён и не блокирует мониторинг, инструкция повторена другим участником.

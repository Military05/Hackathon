# Q — тестировщик обеих линий

## Твой результат

Команда знает, какой конкретный SHA работает, какие функции проверены и какие баги блокируют сдачу. Ты начинаешь до кода с критериев, а сразу после beta-1 — с полной проверки её основных функций, пока обе пары продолжают разработку.

Читать: [старт](../START_HERE.md), [план](../TASK_03_PLAN.md), [контракты](../CONTRACTS.md), [TESTING](../TESTING.md), [RUNBOOK](../RUNBOOK.md).

## До beta-1

1. Уточни допустимость симулятора и обязательные требования.
2. Составь D1–D4 и normal сценарии, ожидаемые ids/status.
3. Проверь, что правила зон/допусков описаны, а не придуманы после бага.
4. Подготовь чистую папку/клон, данные и команды.
5. По мере PR проверяй запуск и полный минимальный сценарий.
6. Smoke перед beta-1 — короткий запуск, реальный ввод, отображение, хотя бы один рабочий incident; все D1–D3 должны быть доступны для дальнейшей проверки.

Не требуй законченного агента перед стартом параллельной работы: он входит в F1.

## Сразу после beta-1

Проверь фиксированный снимок, например во втором клоне:

~~~powershell
git clone https://github.com/Military05/Hackathon.git Hackathon-QA
cd Hackathon-QA
git fetch origin --tags
git switch --detach beta-1
git rev-parse HEAD
~~~

Тег создаётся после скелета; до этого команда не сработает. В detached HEAD не коммить. Для собственных тестов создавай отдельную именованную qa-ветку.

В журнал записывай SHA, окружение, commands, PASS/FAIL/BLOCKED. Старый результат не относится к новому push.

## Основные проверки

| Сценарий | Что должно произойти |
| --- | --- |
| Normal movement/access | Нет forbidden/unauthorized incidents |
| D1: V1 вошёл в запрещённую зону | Один incident с zone/asset и position evidence |
| D2: U без допуска вошёл в W | Incident со ссылкой на access event и версией разрешений |
| D3: датчик перестал отправлять heartbeat | После threshold один offline incident, при возврате восстановление |
| Неправильный JSON/id/координаты | Согласованная ошибка, facts не изменены |
| Повтор одинакового event | Идемпотентность, нет дубля |
| Поздний position event | История сохранена по контракту, текущая позиция не откатилась |
| Перезапуск | Факты и incidents сохраняются, таймер не даёт неконтролируемых дублей |
| Ollama недоступна | Карта/правила продолжаются, analysis failed/unavailable |
| ML не обучена | Явный not_trained, не normal |

Тест на границе зоны нужен отдельно: boundary считается внутри.

## Проверка нейросети B2

Проверь факт собственного обучения, сохранённый Pipeline, feature_version, независимые episode splits, отсутствие label leakage и реальные метрики.

Для новой модели используй отдельные normal/anomaly эпизоды. False positive — реальный результат, который записываем. Score не подписывается как доказанная вероятность аварии.

Проверь одинаковые offline/online features, insufficient_data и отсутствие дублирующих incidents на перекрывающихся окнах.

## Проверка агента B1

- Реальные tool calls видны в trace, это не заранее написанная фраза.
- Event ids в итоговом evidence существуют и были получены инструментами.
- У valid employee агент не выдумывает отсутствие допуска.
- Unknown id не превращается в выдуманный объект.
- Гипотеза отмечена как hypothesis, точные факты совпадают с базой.
- Неправильный tool/аргумент отклонён приложением.
- Предел времени/шагов завершает job, без вечного ожидания.
- Текст события, похожий на команду модели, не меняет допустимые tools.
- Повторный анализ использует подходящий snapshot; новый evidence не получает старый cached ответ.

## Приоритет и очередь

P0: запуск, потеря фактов, не работает основной показ.
P1: неверное обязательное поведение, некорректный evidence, неправильно заявленная готовность модели.
P2: второстепенный интерфейс.

Очередь: P0 → исправления → совместный кандидат → обязательная F1 → оставшаяся beta-1 регрессия → косметика. Основные функции beta-1 обязательны, но найденный P0 прерывает обычную очередь.

Автор до передачи делает самопроверку. Если нет команды/данных/ожидания, верни PR для дополнения и бери следующий готовый.

## Баг и перепроверка

GitHub Issues → «Ошибка». Укажи source SHA, шаги, expected/actual, приоритет и затронутые линии main/F1. Общий bug может требовать двух PR; процесс в PROCESS_IMPROVEMENTS.

После исправления проверь новый SHA, оставь новую строку журнала. Тег beta-1 не двигаем. Исправление в личной ветке ещё не значит попадание в обе линии.

## Твои ветки

Тесты основы: qa/core-scenarios от main → PR main.
Тесты F1: qa/f1-evidence от feature/beta1-f1 → PR в эту ветку.
Не отправляй фиксы в ветку автора без отдельной договорённости.

## Финал

После main → F1 фиксируете совместный head и временно прекращаете его менять. Проверяешь D1–D4, нейросеть, агент, восстановление и запуск. После merge повторяешь обязательный сценарий на main.

С чистого клона повторяешь RUNBOOK. Final tag только на проверенном SHA. Сохраняешь log и demo fixtures; не выдаёшь replay ответа за живую работу агента.

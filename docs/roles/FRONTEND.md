# A2 — разработчик фронтэнда и карты

## Твой результат

Диспетчер видит предприятие, движение, доступ, состояние датчиков и происшествия. Он может открыть evidence и запросить объяснение. Предпочтение пользователя «возможно консоль» не ограничивает выбранный №3: делаем браузерную карту, служебные команды могут быть консольными.

Читать: [старт](../START_HERE.md), [план](../TASK_03_PLAN.md), [контракты](../CONTRACTS.md), [запуск](../RUNBOOK.md).

## Первые действия

1. Согласуй с A1 JSON site/assets/incidents и локальные x/y 0..100.
2. Создай страницу в src/interface/web/.
3. Нарисуй SVG viewBox=0 0 100 100 по общему site, не второй независимый список зон.
4. Подключи GET /api/site и /api/assets.
5. Покажи транспорт и карточку первого incident.
6. Пока backend не готов, используй явный mock с тем же JSON, потом замени на реальный API до beta-1.

## Твои файлы

src/interface/web/ и UI-тесты/сценарии. Общий map entrypoint меняешь ты. B1/B2 подключают свои панели через согласованный module/component contract и маленькие PR.

A1 владеет site.json; правку geometry сначала согласуй с ним, чтобы рисунок и rules не разошлись.

## Минимум beta-1

- План: W1/W2/P1/P2/O1/G1, дороги, Z1/Z2.
- Транспорт V1–V3, последняя позиция, время последнего события.
- Список происшествий с type, asset/building, время, severity, status.
- Карточка с evidence и источником demo.
- Показ online/offline датчиков.
- Действия acknowledged/closed через API, без ручного изменения фактов.
- Состояния loading/empty/error, повтор запроса.
- Опрос данных раз в секунду, один выполняющийся запрос на ресурс; если медленно, не запускай бесконечные перекрывающиеся запросы.

Нет данных — не рисуй «всё нормально». Offline транспорт не выглядит как свежая позиция. Любое внешнее описание выводи текстом, не исполняй как HTML.

## Beta-2

Фильтры incidents по типу/объекту/status, удобная карточка здания, улучшение ошибки связи, восстановление polling после сбоя. Продолжай маленькими PR в main.

## Интеграция ML и агента

Панель модели показывает model_version, score, threshold, ready/insufficient_data/error и подпись «оценка модели». Не превращай score=0.8 в «80% опасности».

Кнопка «Проанализировать» создаёт agent_job, показывает queued/running/completed/failed. HTTP 202 ещё не содержит итоговый текст. Повторно опрашивай job, не отправляй новый на каждый кадр.

Итог разделяет facts, hypotheses, recommendations и evidence. Дай раскрыть tool trace, чтобы на защите было видно фактическое чтение системы.

Если агент недоступен, карта и incidents продолжают работать. Сохранённый пример помечай replay, не выдавай за живой ответ.

Beta-2 делай в новой core/beta2-interface от свежего main. Перед PR включи origin/main в свою ветку и проверь реальные endpoint.

## Самопроверка

- SVG совпадает с координатами backend, границы понятны.
- Реальное событие перемещает объект.
- Нормальный сценарий не окрашивает всю карту тревогой.
- D1/D2/D3 видны в списке и карточке.
- Нельзя случайно отправить два ack через повторный клик.
- Сервер недоступен — видим понятную ошибку, данные не становятся свежими.
- Перезапуск страницы не создаёт фиктивные incidents.
- Тексты, время UTC/локальное отображение согласованы.

Передай QA сценарий кликов и ожидаемый результат на конкретном SHA.

## Демонстрация

Первые 30 секунд покажи обычную работу. Затем B2 запускает D1/D2/D3/D4. Выберите incident, откройте evidence, запросите анализ агента. Не перегружайте главную страницу техническими подробностями; trace доступен в отдельном раскрытии.

# Егор М. — вход, карта и рабочие места диспетчеров

Текущее поручение v5 добавляет вход/регистрацию, минимальную админ-панель и КПП.
Старые указания «без формы регистрации» и выбор личности через URL заменены.
ML/ИИ и внешний симулятор остаются отдельными модулями Гриши/Гаджи.

Сначала прочитайте [PRODUCT_V5](../PRODUCT_V5.md), [CONTRACTS](../CONTRACTS.md),
[DISPATCH_OPERATIONS](../DISPATCH_OPERATIONS.md), [AUTH_SECURITY_V5](../AUTH_SECURITY_V5.md),

## Область

`src/interface/web` и интерфейсные проверки. Leaflet CRS.Simple и локальные
JS/CSS рисуют условный план из того же site.json, который использует сервер.
Геометрию меняйте согласованно с Егором С.; отдельный GPS/3D-сервис не нужен.

## Рабочий порядок

1. Сначала /api/auth/status и /api/auth/me. Без входа показывается форма,
   старые запросы рабочего места не продолжаются. Регистрация — pending;
   сектор назначается администратором, а не селектором пользователя.
2. Вход держит user/CSRF в памяти страницы; cookie HttpOnly читает браузер.
   Все рабочие запросы/CSV используют X-Expected-User, изменяющие — CSRF.
   401 возвращает ко входу; 409 session_identity_changed требует обновить
   старое рабочее место. Не повторяйте действия автоматически другой личностью.
3. После входа фиксированный профиль: 1 — логистика/склады, 2 — производство,
   3 — КПП. Селектор не меняет права; URL operator не источник личности.
4. Три аккаунта проверяйте в разных browser profiles/браузерах/устройствах:
   обычные вкладки разделяют cookie. Несколько вкладок одного аккаунта допустимы.
5. Карту, журнал и КПП размещайте плотными колонками; пустая карточка короткая,
   диагностика/сценарии сворачиваются. На узком экране не должно быть
   горизонтального переполнения или скрытых основных кнопок.
6. Красная штриховка — запрет всего транспорта, оранжевая — по допуску;
   секторные контуры без заливки. Голубую заливку не добавляйте. Подписи зданий
   помещаются внутрь; сокращение/ID используется только при малом масштабе.
7. «Мой сектор» использует focus_bounds, не весь разрозненный набор участков.
   Выбор карточки только подсвечивает; ShowOnMap меняет камеру явно.
   Реальные position интерполируются максимум до 15 кадров/с; UI не генерирует их.
8. Последний сигнал показывается у объекта/датчика. Диагностика читает здоровье,
   ручная проверка не создаёт heartbeat и не обещает физическую исправность.
9. shift показывает людей 0/3→3/3, затем position той же shift_id. Не запускайте
   транспорт клиентским таймером и не выдавайте ожидание за потерю датчиков.
10. Фильтры КПП, страницы, период и CSV говорят об ограничении 200; CSV действий
    default1000/max2000. Сводка считает серверные успешные действия.
11. Админ-панель: заявки, назначение профиля, блокировка, аудит. Видимость кнопки
    удобна пользователю, но полномочия каждой операции проверяет сервер.
12. Polling раз в секунду без накопления; presence раз в 3 секунды. Не стирайте
    reason, выбранный случай, фильтры и камеру при новых данных. Revision и
    request_id отправляются из показанной карточки; can_claim управляет кнопкой
    и не заменяет серверную проверку.

## Отдельные модули

Панели ML/ИИ используют только реальные подключённые статусы/версии/evidence.
Недоступность отображается явно. Кнопка анализа не задерживает карту/журнал.
С Гаджи согласуйте HTTP-сессию и CSRF, с Гришей — источник/координаты/артефакт;
не редактируйте их каталоги ради интерфейсной задачи.

```powershell
node --check src/interface/web/app.js
node --test tests/interface.test.js tests/map-view.test.cjs tests/sensors-panel.test.cjs tests/interface/*.cjs

```

Далее живой браузер: вход/заявка/admin, три профиля, shift, запрещённый проход,
claim/передача, сохранность ввода, zoom и CSV. Тесты mock не подтверждают общий
SQLite или реальный ИИ. Передайте Лие ветку, полный SHA, команды, сценарии кликов
и ограничения. Файлы/ветки изолированы, итоговое main объединяет координатор.
Основные этапы во время разработки показывайте визуально в правой панели,
а после приёмки оставляйте обычное рабочее приложение.

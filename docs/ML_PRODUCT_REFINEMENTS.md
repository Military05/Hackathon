## Завершённые измерения

Только существующее окружение Release: Python 3.12.10, NumPy 2.3.5,
scikit-learn 1.8.0, joblib 1.5.3; CPU, один поток, без установок.
Train/validation/test — 666/222/222 целых непересекающихся эпизода,
seeds 20261018/20261019/20261020. Scaler обучен только на train, порог
выбран только на validation; test не использовался для обучения/порога.
Генерация 8,619 с; полный train 61,810 с, из них fit 2,063 с,
69 итераций без convergence warnings, 10305 обучающих окон.

На независимом test найдены 110/111 аномальных эпизодов, один пропущен;
один эпизод с ложной тревогой. Медианная задержка обнаружения 30 с,
максимальная 45 с модельного времени. Extractor + одиночный inference:
124 измерения, median 1,779 мс, p95 2,455 мс, max 3,651 мс.
Полный отчёт: `models/movement-v1/evaluation.json`.
Это синтетическая проверка, а не промышленная точность или нагрузочный benchmark.

До поступления запрета на дальнейшие тесты завершился replay реальных
DemoRunner → Event → Service → SQLite → обученная MLP: по 180 секунд
модельного времени в десяти сценариях, 118,568 с фактического выполнения.
Этот завершённый отчёт не обозначен как прерванный. Все базы временные;

Итого 1080 наблюдений, включая 900 оценённых окон. У пяти штатных сценариев
нет ложных ML-тревог; все три актуальные аномалии дали фактическую модельную
тревогу V1. Одна collision в logistics — отдельный выявленный дефект штатного
движения/правил, поэтому отсутствие всех тревог в logistics не заявляется.
Результат передан координатору. Полный report:
`models/movement-v1/factory_acceptance.json`.
Adapter median 8,755 мс, p95 11,919 мс, max 79,707 мс, с чтением SQLite.
Сравнение с прежней моделью не запускалось: существующий comparator получает
10 с истории и не обеспечивает необходимые v2 30 с.

До запрета выполнены 18 проверок `test_movement.py` + `test_training.py`:
PASS за 4,77 с. Первоначальный запуск дал семь ошибок setup из-за отсутствия
доступа к глобальному pytest temp; повтор с `--basetemp=tmp/product-ml-unit`
прошёл. Также до запрета подтверждены: прежний bundle отвергает новую карту,
новый bundle готов на новой карте и по-прежнему отвергает непроверенное
изменение карты; порядок 13 признаков сохранён, веса действительно изменились.

После прямого запрета пользователя новые тесты и проверки не выполнялись.
Дополнительная проверка реальной MLP через planned pause/resume не запускалась:
её отклонила автоматическая проверка разрешений. Проверка уже опубликованного
комплекта, полный pytest, recovery/evidence timeline, живой HTTP→MLP→Qwen,
короткая пауза/перезапуск сценария с 30-секундной историей, целевые ноутбуки и
многоклиентская нагрузка — NOT RUN в этой поставке. Текущий ML-adapter может
читать последние измерения разных сегментов в пределах 30 с; данный
replay этот случай не проверяет. Новые тесты не добавлялись.

## Повторение владельцем ML

Эти команды описывают существующий workflow и в этой поставке повторно
после запрета не выполнялись. Из корня проекта с закреплённым Python 3.12:

```powershell
python -m src.ml.factory_dataset --output data/generated/product-route-v2
python -m src.ml.train --input data/generated/product-route-v2 --output artifacts/local/product-route-candidate
python -m src.ml.evaluate --input data/generated/product-route-v2 --model artifacts/local/product-route-candidate/movement.joblib
```

Измеренный replay использовал `replay_factory(..., seconds=180, scenarios=...)`
из `src.ml.factory_acceptance` с десятью сценариями таблицы. Поставка содержит
реальные сохранённые результаты, а не подменённые ответы inference.
Для загрузки bundle требуется согласованный перезапуск существующего сервера
с прежней рабочей SQLite; он не выполнялся в этой задаче. История БД сохраняется.

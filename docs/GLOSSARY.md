# Словарь: что означают слова в наших инструкциях

Не нужно учить весь список. Найди незнакомое слово и вернись к своей задаче. Названия файлов, веток, полей и команд остаются английскими: именно так их нужно вводить или искать в коде.

## Люди и версии проекта

| Слово | Простое объяснение |
| --- | --- |
| Frontend / фронтенд | Интерфейс: карта, кнопки, карточки, то, что видит пользователь |
| Backend / бэкенд | Серверная часть: приём данных, хранение, правила и ответы интерфейсу |
| Full-stack | Разработчик, который делает и логику, и интерфейс своей функции |
| QA / Q | Наш тестировщик |
| A1 / A2 | Разработчик серверной части / разработчик интерфейса |
| B1 / B2 | Разработчик агента / разработчик симулятора и нейросети |
| beta-1 | Первая запускающаяся версия основы: карта, события и правила |
| beta-2 | Следующая версия основы, которую делает первая пара |
| F1 в процессе разработки | Первая дополнительная функция: нейросеть и агент |
| D1 / D2 / D3 / D4 | Сценарии: запрещённая зона / проход без допуска / потеря связи / необычное движение |

## Git и GitHub

| Слово | Простое объяснение |
| --- | --- |
| Repository / repo | Репозиторий — общая папка проекта с историей изменений |
| Branch | Ветка — отдельная линия разработки |
| main | Общая ветка с объединённым рабочим кодом |
| origin | Имя подключения Git к вашему репозиторию на GitHub |
| clone | Копирование репозитория вместе с историей на свой компьютер |
| git status | Посмотреть свою ветку и изменённые файлы |
| git add | Подготовить выбранные файлы для сохранения |
| git diff | Посмотреть изменения; --cached показывает уже подготовленные |
| commit | Сохранить выбранные изменения в истории Git |
| push | Отправить локальные коммиты на GitHub |
| fetch | Получить сведения о новых изменениях; ещё не включить их в свою ветку |
| pull --ff-only | Получить обновления и продвинуть ветку, только если истории не разошлись |
| merge | Объединить изменения двух веток |
| PR / Pull Request | Запрос: «проверьте мои изменения и объедините их в выбранную ветку» |
| base | Ветка назначения запроса — куда объединяем |
| compare / head branch | Ветка автора — откуда берём изменения |
| head / HEAD | Текущая вершина ветки или текущая выбранная версия |
| SHA | Идентификатор конкретного коммита; узнать: git rev-parse HEAD |
| tag | Тег — имя зафиксированной версии, например beta-1 |
| detached HEAD | Просмотр конкретной версии без активной рабочей ветки |
| review | Проверка изменений другим разработчиком |
| Draft | Черновик запроса: работа ещё не готова к объединению |
| conflict | Конфликт: Git не смог сам совместить изменения; авторы выбирают правильный результат |
| revert | Новый коммит, отменяющий изменения прежнего |
| force push | Принудительная замена истории удалённой ветки; в нашем процессе не используем |
| Issue / Issues | Задача или сообщение об ошибке / список таких записей |
| Backlog | Список запланированных задач |
| Collaborator | Участник с доступом к репозиторию |
| Owner / Member / Write | Владелец организации / её участник / право изменять код |
| CI | Автоматические проверки после отправки кода |
| lock-файл | Файл точных версий зависимостей; используем, если выбранный инструмент его создаёт |
| Refs #12 / Closes #12 | Ссылка на задачу №12 / команда закрыть её после объединения |

## Приложение и данные

| Слово | Простое объяснение |
| --- | --- |
| API | Согласованный способ запросить данные у сервера или отправить их |
| Endpoint | Адрес конкретной операции сервера, например /api/events |
| GET / POST / PATCH | Получить данные / отправить новые / изменить часть существующих |
| HTTP | Протокол общения интерфейса с сервером |
| JSON | Текстовый формат данных: названия полей и их значения |
| SVG | Векторная картинка; у нас схема предприятия |
| UI / UX | Интерфейс / удобство его использования |
| UTC | Мировое время; храним единообразно, показываем в согласованном часовом поясе |
| Event | Событие: показание позиции, факт прохода или сообщение о работе датчика |
| Payload | Содержимое события: координаты, объект, здание и другие нужные поля |
| Raw | Исходные данные до преобразований |
| Asset | Отслеживаемый объект: машина или сотрудник |
| Sensor | Датчик |
| Building / zone | Здание / контрольная зона |
| Site | Общая схема предприятия |
| Policy / permissions | Правила и разрешения: кому куда можно |
| Heartbeat | Сообщение датчика «я работаю» |
| Incident | Происшествие: система обнаружила нарушение или необычное поведение |
| Evidence | Исходные события и данные, на которые опирается вывод |
| Severity | Важность происшествия для диспетчера |
| Status / state | Состояние записи или компонента |
| Lifecycle | Путь происшествия: появилось, замечено, восстановлено, закрыто |
| Recovery | Возвращение к нормальной работе |
| Ack / acknowledged | Диспетчер подтвердил, что увидел происшествие |
| Snapshot | Снимок данных на определённый момент |
| Mock | Временная имитация ответа вместо ещё не готового компонента |
| Demo | Демонстрационные данные; у нас синтетические |
| Simulator | Программа, которая создаёт тестовые показания датчиков |
| Polling | Повторное получение обновлений через заданный интервал |
| Health / readiness | Проверка состояния / готовности компонентов |
| Loading / empty / error | Загружается / данных нет / произошла ошибка |
| Online / offline / unknown | Связь есть / связь потеряна / состояние ещё неизвестно |
| Open / acknowledged / closed | Открыто / увидено диспетчером / закрыто |
| Critical / warning / info | Высокая важность / предупреждение / информация |
| Entrypoint | Файл или функция запуска приложения |
| Router / route | Модуль адресов сервера / конкретный маршрут запроса |
| Schema | Структура данных или таблиц базы |
| Handler | Функция, которая обрабатывает запрос |
| Scheduler | Таймер фоновых проверок |
| Worker | Обработчик задач |
| Event loop | Цикл обработки запросов; долгие вычисления не должны его останавливать |
| Thread executor | Выполнение вычислений в отдельном потоке |
| Lifespan | Этапы запуска и остановки приложения, где создаются фоновые задачи |
| Runtime | Данные и процессы во время работы приложения |
| Idempotency / идемпотентность | Повтор одного и того же запроса не создаёт второй такой же результат |
| Side effects | Дополнительные действия: создание происшествия, обновление позиции |
| Traceback | Техническое описание ошибки; не показываем его обычному пользователю |
| 201 / 202 / 409 / 422 / 503 | Создано / принято в очередь / конфликт / неверные данные / сервис недоступен |

## Нейросеть и оценка

| Слово | Простое объяснение |
| --- | --- |
| ML | Машинное обучение |
| MLP / MLPClassifier | Небольшая многослойная нейросеть / её реализация в библиотеке |
| Feature / features | Числовой признак / признаки, например средняя скорость |
| Extractor | Функция, вычисляющая признаки из показаний |
| Episode | Целый отрезок движения с общими параметрами сценария |
| Window | Окно — небольшой промежуток показаний для одной оценки |
| Seed | Начальное число генератора: помогает повторить те же данные |
| Label / class | Правильная метка примера / класс ответа |
| Normal / anomaly | Обычное / необычное поведение |
| Train / training | Обучающая часть данных / процесс обучения |
| Validation | Отдельные данные для выбора настроек и порога |
| Test | Независимые данные для итоговой проверки |
| Split | Разделение данных на части |
| Leakage | Утечка правильного ответа или тестовых данных в обучение; оценка становится нечестной |
| Scaler / StandardScaler | Приведение числовых признаков к сопоставимому масштабу |
| Pipeline | Цепочка преобразований и модели, сохранённая вместе |
| Threshold | Порог: при каком значении включается тревога |
| Score | Числовая оценка модели; не гарантированная вероятность аварии |
| Inference | Применение обученной модели к новым данным |
| Evaluation | Измерение качества модели |
| Baseline | Простой алгоритм для сравнения с нейросетью |
| Confusion matrix | Таблица правильных ответов и ошибок |
| TP / FP / TN / FN | Найденная аномалия / ложная тревога / верно обычное / пропущенная аномалия |
| Precision | Какая доля тревог была правильной |
| Recall | Какая доля всех аномалий была обнаружена |
| F1 в отчёте модели | Общая метрика precision и recall; не название дополнительной функции |
| Convergence | Сходимость обучения; предупреждение может означать, что обучение не завершилось |
| Artifact | Сохранённый результат: обученная модель и её параметры |
| Metadata / manifest | Описание версий и параметров / перечень данных и частей |
| Hash | Контрольный отпечаток файла |
| Cooldown | Пауза перед повторной тревогой |
| Insufficient_data / not_trained | Недостаточно данных / модель ещё не обучена |

## Проверки и передача

| Слово | Простое объяснение |
| --- | --- |
| Smoke test | Короткая проверка запуска и основного сценария |
| Regression | Повторная проверка, что изменения не сломали прежнюю работу |
| Fixture | Подготовленные тестовые данные |
| Expected / actual | Ожидаемый / фактический результат |
| PASS / FAIL / BLOCKED / NOT RUN | Успешно / ошибка / заблокировано / не запускалось |
| TODO / IN PROGRESS / IN REVIEW / DONE | Запланировано / в работе / на проверке / завершено |
| P0 / P1 / P2 / P3 | Приоритет: блокирует работу / важная ошибка / неудобство / оформление |
| Freeze | Момент прекращения новых функций перед сдачей |
| Release / gate | Выпуск / обязательные условия готовности |

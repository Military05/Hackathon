# Служебный объезд, пауза и общий отчёт

Уточнение продукта от 9 октября 2026. Этот документ заменяет прежнее описание
`stop` в FACTORY_TRAFFIC_V4, PRODUCT_V5 и GATE_SHIFT_V5: остановка через API
теперь приостанавливает текущий эпизод и смену; явный новый старт завершает
прежнюю смену и создаёт новый эпизод. Перезапуск сервера продолжение не сохраняет.

## Служебный маршрут

Личный V3 согласован в `routes`, `demo_routes` и `safety_routes`. Он идёт
по существующим связанным проездам от энергоцентра E1 к насосной E2, медпункту M1
и офису O1, затем возвращается через центральный проезд. Маршрут охватывает
энергоцентр, южную часть производства и офисный участок. Новых дорог, прохода
сквозь здания или разрешения въезда в закрытые зоны нет. Точки `route_stops`
описывают посещаемые подъезды; генератор сохраняет прежнюю остановку у основного
назначения E1, без обещания отдельной остановки у каждого корпуса.

В сценарии `service` («Объезд технической службы», пункт 4) едет только V3.
Погрузчики V1/V2 стоят в безопасных точках (3,16)/(96,60), статус `parked`.
В «Обычной работе» V3 также следует этому длинному маршруту. Перед каждым
объездом он ждёт у безопасного подхода к энергоцентру, если заданные маршруты
погрузчиков не оставляют консервативный свободный интервал на весь объезд.
Во время ожидания `state=yielding`, ход по маршруту заморожен; это планирование
встроенного демо, не новое правило безопасности или прогноз настоящей аварии.
Провокационные сценарии пересечения и нарушений не используют это ожидание.

Они продолжают посылать обычные position Events, остальные источники — heartbeat
раз в секунду. Позиции и связь припаркованных машин остаются свежими.

## Управление одним эпизодом

| API | Результат |
| --- | --- |
| POST `/api/demo/start`, `{"scenario":"service"}` | Новый эпизод, elapsed=0, новый run ID, счётчики и однократные проходы сброшены |
| POST `/api/demo/stop`, `{}` | Пауза после завершения текущего измеренного кадра |
| POST `/api/demo/resume`, `{}` | Продолжение того же эпизода с последнего измеренного elapsed |
| GET `/api/demo/status` | Общее состояние и разрешённые текущей сессии сценарии |

На паузе `running=false`, `paused=true`, `can_resume=true` для уполномоченного
пользователя; `paused_at` содержит UTC-время паузы. `vehicle_states.*.paused=true`.
`scenario`, `started_at`, `elapsed_seconds`, `event_count/events_sent`, run ID,
последовательность Event, однократные проходы КПП и shift_id сохраняются.
Пауза не заканчивает ни `gate_checks`, ни фазу `transport` смены.
Первый кадр продолжения имеет те же координаты и elapsed; далее время идёт
от новой monotonic-точки отсчёта. Проходы U1/U2/U3 не дублируются.
Повторная пауза безопасна. Resume без доступной паузы — `409 demo_not_paused`.
Лишние параметры stop/resume — `422 extra_parameters`.

Права resume повторяют start/stop: только свой сценарий либо администратор;
чужой сектор — `403 scenario_sector_required`. Сессия определяет профиль,
подмена X-Demo-Operator не помогает. CSRF, Origin и X-Expected-User действуют
как для остальных изменений; admin получает разрешение только на управление
демо, без права выполнять диспетчерские действия. GET status скрывает can_resume
для чужого сектора. Внешний симулятор без resume сообщает 503 и не изменяется.

## Времена и контроль на паузе

Во время паузы генератор не пишет position, heartbeat или access Events.
Не растут elapsed и счётчики, координаты не синтезируются. `last_seen`,
`last_received_at`, время исходных Event и возраст `age_seconds` остаются честными:
возраст растёт по реальному времени, позиция может стать `unknown`/`stale`.
API явно добавляет `monitoring_paused=true` к последним измерениям текущего
встроенного эпизода. Интерфейс показывает «Пауза», не выдуманный свежий сигнал.

Только этот встроенный run исключается из автоматического контроля молчания,
устаревания зон и парного движения. Уже созданные условия сохраняются;
плановая пауза не создаёт sensor_offline и не меняет их в unknown.
Для датчика `monitoring_age_seconds` исключает длительность плановых пауз после
его последнего настоящего сигнала. `status=online/offline` и детектор потери
связи используют этот контролируемый возраст; `age_seconds` всегда показывает
фактический возраст. Поэтому продолжение внутри заданного молчания HB-QA
не вызывает преждевременную тревогу из-за времени паузы. Новый heartbeat
сбрасывает возраст обычным способом; timestamps не переписываются.

Первый кадр после продолжения начинает новый измеренный отрезок безопасности:
collision не проводит линию через паузу. Штатное восстановление требует двух
полученных свежих подтверждений. Периодический MLP не оценивает приостановленные
источники; начатый до паузы расчёт этого run отбрасывается по версии мониторинга.
Новый внешний Event того же датчика не имеет demo-run префикса и продолжает
контролироваться; внешние потоки, ИИ-задания и реальные сроки передачи случаев
не приостанавливаются. Модули ML/агента/внешнего симулятора не редактировались.

## Один CSV действий всех диспетчеров

Администратор скачивает существующий API:

`GET /api/dispatch-history/export.csv?scope=all&limit=2000`

Это один общий файл с реальной сохранённой историей всех профилей. Колонка
**Диспетчер** подписывает исполнителя каждой операции; системные строки
(например, «Обнаружено») сохраняются отдельно в той же таблице.
Собственный отчёт диспетчера: `scope=mine` (по умолчанию).
Чужие собственные записи не выдаются; `scope=all` требует admin (иначе 403).
Предел — последние 1000 записей по умолчанию, максимум 2000; 2001 даёт 422.
UTF-8 BOM, разделитель `;`, русские колонки и действия, время МСК,
защита от формул в текстовых CSV-значениях сохранены.

## Совместимость MLP

Текущий адаптер владельца ML проверяет SHA-256 всего `site.json` относительно
обучающего набора. Удлинение V3 меняет этот SHA: прежний артефакт при запуске
WithAI честно сообщает `artifact_invalid` и просит новую проверку/обучение.
Правила, события, КПП и отчёты продолжают работать. Веса, метаданные и модули
ML не изменялись; их обновление и фактическая приёмка относятся к отдельной
поставке владельца ML. Это ограничение нельзя выдавать за готовую работающую MLP.

## Проверка

`tests/runtime/test_product_scenarios_reports.py` использует только временную SQLite.
Проверяет движение только V3, свежие стоящие погрузчики, нормальные полученные
отрезки V3 за 1200 demo-секунд с ожиданием свободного интервала, паузу смены и продолжение
без дублей, длинную паузу внутри молчания HB-QA, живой внешний источник,
sector/CSRF/Expected-User и общий admin CSV с действиями трёх диспетчеров.
Команды и фактический результат указываются в передаче полного SHA.

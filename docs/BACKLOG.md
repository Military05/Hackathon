# Начальные задачи команды

Это список заготовок для Issues. Идентификаторы P00–P11 — номера строк этого плана, **не номера Issues**. Реальные задачи создаём на GitHub по шаблону «Задача команды», добавляем ссылки и assignee после распределения ролей.

## Подготовка и первый цикл

| ID | Задача | Владелец | База | Готово, когда | Зависимость / Issue |
| --- | --- | --- | --- | --- | --- |
| P00 | Доступ, клон и пробный полезный PR | Каждый | main | Каждый может push личной ветки | приглашение; ссылка |
| P01 | Разобрать условие и выбрать минимум | Все; решение руководителя | main | Пользователь, сценарий и формат записаны в TEAM | после получения задания |
| P02 | Согласовать контракт v1 | A1 + A2; просмотр B1/B2 | main | Вход/выход/ошибки и пример в CONTRACTS | P01 |
| P03 | Минимальное ядро | A1 | main | Реально выполняет обязательный сценарий | P02 |
| P04 | Минимальный интерфейс | A2 | main | Ввод вызывает ядро и показывает результат | P02; заглушка до P03 |
| P05 | Сценарии и тестовые данные | QA + помощь B1/B2 | main | Есть normal/error, повтор и выход | P01/P02 |

B1/B2 до beta-1 берут самостоятельные полезные подзадачи: примеры, сценарии, тесты, план F1, заглушку по контракту. Если скелет блокируется, помогают паре A.

## После beta-1: три потока одновременно

| ID | Задача | Владелец | База | Готово, когда | Зависимость / Issue |
| --- | --- | --- | --- | --- | --- |
| P07 | Улучшения основы для beta-2 | A1 + A2 в отдельных задачах | main | Обязательные улучшения работают, контракт согласован | beta-1 |
| P08 | Функция F1: два проверяемых участка | B1/B2, личные ветки | feature/beta1-f1 | Логика и интерфейс вместе работают | beta-1, контракт F1 |

| P10 | Интеграция beta-2 + F1 | Все; один оператор | feature/beta1-f1 → main | Совместная проверка, merge, повтор проверки main | P07/P08; баги P09 учтены |
| P11 | Финальная проверка и сдача | QA + все | main | Чистый клон, запуск, инструкции, final-v1 | P10 или сокращённый проверенный объём |

## Карточка задачи

- Результат в одной фразе.
- Роль/конкретный assignee.
- Base branch и имя личной ветки.
- Изменяемые файлы, общий файл и его владелец.
- 2–4 критерия приёмки.
- Зависимость от другой задачи и версия контракта.
- Команды/данные проверки.
- Приоритет и крайнее время интеграции.

Не используйте общую карточку «сделать весь бэкэнд» как единственную задачу на два дня. Разделите обязательный сценарий и дальнейшие улучшения на маленькие PR.

## Статусы

TODO → IN PROGRESS → IN REVIEW → READY FOR QA → TESTING → DONE.

BLOCKED: причина + кому нужен вопрос + ссылка. FAILED при проверке возвращает задачу автору и создаёт/связывает воспроизводимый баг.

Для маленькой задачи статусы можно держать в тексте Issue без отдельной доски. При желании используйте GitHub Projects; создание доски не является условием начала работы.

## Итог дня

Каждый оставляет в своей Issue: готово, следующий шаг, блокировка, ветка/PR, последний опубликованный SHA. Работа только на ноутбуке автора не считается переданной команде.

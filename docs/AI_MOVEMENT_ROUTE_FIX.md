# Анализ движения и отклонения от маршрута

Исходный main: `9f11af6bb4c9a0f13a6ebca65f30a5bed60db512`.
Ветка: `codex/fix-movement-route-analysis`.

В сохранённой резервной копии маршрутное задание завершалось с
`Observation evidence was not read by tools`: оценка без событий попадала в
доступные модели варианты фактов. Такие варианты теперь исключаются; строгий
валидатор продолжает их отклонять, если провайдер проигнорирует схему.

При повторном запуске этого исторического снимка настоящий LM Studio также
отклонил запрос: 9764 токена при контексте 8192. Передача модели теперь содержит
первое измерение каждого объекта и 12 последних событий. Явные метаданные
сообщают о выборке и пропущенной истории. Полный ограниченный snapshot,
показатели, доказательства и их проверка остаются неизменными. Финальные
варианты событий берутся только из показанных модели событий.

Для model_anomaly схема требует весь кортеж status/score/threshold связанной
оценки. Прежняя схема отдельных вариантов допускала повторение одного поля.
Ответ не исправляется программой: при отказе валидации допускается новый ответ
модели в пределах прежних трёх запросов и общего таймаута. После исчерпания
лимита неподтверждённый результат не публикуется.

Новое производное поле monitoring_age_seconds исключено из аналитического
снимка, как и age_seconds. Смена реального статуса датчика и события по-прежнему
меняют snapshot_id. Версия инструкции изменена для разделения кэша.

Свежие записи рабочей базы недоступны текущей сессии Windows; причиной
конкретного свежего MLP-отказа нельзя считать повторение поля без просмотра
его диагностических данных. Исправление закрывает воспроизводимый дефект схемы.

Применение: запускать проверенный checkout с прежними настройками Qwen,
абсолютным DISPATCH_DB существующей базы и включёнными AI/ML. Сначала backup API,
затем переключение одного worker на 8000. Историю, веса и аккаунты не очищать.

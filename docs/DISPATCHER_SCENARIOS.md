# Личные списки сценариев

Ветка разработки: `codex/dispatcher-scoped-scenarios`.
Исходный main: `87129193ad49e12b694872e71109f662a5ad9919`.

Исправлен список демонстрационных сценариев, а не список происшествий для ИИ.
Раньше `/api/demo/status` возвращал всем полный список, а `/api/demo/start`
проверял только существование сценария. Теперь список и право запуска связаны
с профилем реальной сессии. Подставленный X-Demo-Operator не меняет полномочия.
CSRF и Expected-User сохранены. Остановить чужой сценарий может администратор.

Для текущей карты:

| Рабочее место | Доступные сценарии |
| --- | --- |
| Диспетчер 1, склады | Штатная работа, доставка, въезд без допуска, отклонение маршрута, пересечение и безопасный разъезд транспорта, служебный транспорт в закрытой складской зоне, красная/оранжевая зоны, три аномалии движения |
| Диспетчер 2, производство | Штатная работа, потеря сигнала HB-QA, погрузчик в производственной зоне |
| Диспетчер 3, КПП и офис | Штатная работа, объезд технической службы, смена персонала, проход без допуска |
| Администратор | Все сценарии, включая несколько одновременных происшествий |

Сектор вычисляется по объекту назначения, датчику или зоне через существующую
`Service._responsibility`. Поэтому сценарий служебной машины в Z4 относится
к складам, несмотря на принадлежность самой машины другому рабочему месту.
Общие дороги используют ту же привязку к назначению транспорта, что происшествия.
Неизвестные новые сценарии недоступны диспетчерам до добавления явной привязки.

Интерфейс повторно проверяет метаданные сектора и принадлежность ответа текущему
оператору. При смене профиля старый выбор очищается; чужой или подставленный пункт
не отправляется на сервер. Нельзя сохранить большой список из предыдущего ответа,
когда новый разрешённый список пуст. Под списком указано рабочее место.

Демонстрационный источник по-прежнему общий и выполняет один сценарий одновременно.
Личный список ограничивает целевые демонстрации; он не создаёт три независимые
симуляции и не изменяет маршруты, Events, MLP или ответы Qwen. Штатный фон может
включать транспорт других секторов. На рабочем сервере эти изменения требуют
обновления Python-кода, а не только страницы браузера.

В ветку включены ранее проверенные исправления CI из PR #8: полные тестовые
зависимости и корректная проверка HTTP 403 при попытке принять чужое происшествие.

Проверки выполняются на временных SQLite-базах и тестовом DOM:

```powershell
python -m unittest discover -s tests/runtime -p 'test_*.py' -v
python -m unittest discover -s tests/qa -p 'test_*.py' -v
node --check src/interface/web/app.js
node --test tests/interface.test.js tests/map-view.test.cjs tests/sensors-panel.test.cjs tests/interface/*.cjs
```

Новые HTTP-тесты проверяют три настоящие сессии, подделку заголовка, CSRF,
отказ чужому запуску/остановке до изменения источника и привязку зоны к карте.
Вызовы запуска источника в этих тестах явно заменены AsyncMock; это проверка
авторизации, не приёмка физического полигона, реального Qwen или GPU.

Локальные результаты: runtime — 132 PASS; QA — 18 PASS; интерфейс — 93 PASS;
JavaScript syntax — OK. После дополнительного случая разрешённой остановки
четыре теста HTTP-доступа повторно проверены отдельно.

# Как это делают на предприятиях и что повторяем за два дня

## Применение к нашей новой цели

Три sector-профиля распределяют внимание, общая сводка позволяет помогать, один атомарно назначенный ответственный устраняет неоднозначность. Передача с подтверждением и напоминания/эскалация обязательны в нашем demo; число три — выбранная модель предприятия, не универсальный норматив штата. [Спецификация](DISPATCH_OPERATIONS.md).

HSE рекомендует учитывать распределение ответственности, взаимодействие операторов и нагрузку; тревога должна быть полезной и иметь определённую реакцию. [Control room design](https://www.hse.gov.uk/comah/sragtech/techmeascontrol.htm), [Alarm management](https://www.hse.gov.uk/humanfactors/topics/alarm-management.htm). Эти принципы не означают сертификацию нашего демо.

Локальная LLM сначала выбирается из уже скачанных Bionic моделей, программный API проверяется фактически. [Bionic Local models](https://lmstudio.ai/docs/bionic/models), [LM Studio server](https://lmstudio.ai/docs/developer/core/server). Промышленные примеры ниже — контекст; они не добавляют облако, смены или управление оборудованием в текущий объём.

Если слово незнакомо, открой [словарь простыми словами](GLOSSARY.md). Команды и названия полей не переводим: в коде они должны остаться точными.

Проверка официальных источников: 6 октября 2026. Это примеры опубликованных решений, не статистика доли рынка: нельзя утверждать, что большинство заводов использует именно агентов или определённую LLM (большая языковая модель).

## 1. Сначала инфраструктура данных

В опубликованной архитектуре Siemens Industrial Edge есть подключение устройств через промышленные протоколы, обработка на edge, модель данных и передача событий вышестоящим системам. [Siemens architecture](https://www.siemens.com/en-us/content/architecture-hub/op-center/).

Для нашей задачи аналог — адаптер → валидатор событий → БД → точные правила → карта. Реальные датчики транспорта могут давать GPS/UWB/RTLS, доступ — события СКУД. Конкретный протокол зависит от оборудования. Симулятор заменяет источник, а не весь сервер.

## 2. Числовая модель и языковая модель — разные задачи

Siemens отдельно описывает локальное обнаружение аномалий временных данных на Industrial Edge. Это пример анализа измерений на месте. [Anomaly Detection](https://www.siemens.com/en-gb/products/simatic-apps/anomaly-detection/).

В нашем MVP точные нарушения обнаруживают правила, MLP (небольшая многослойная нейросеть) ищет необычные паттерны движения. Локальная LLM объясняет историю диспетчеру. Она не нужна для вычисления попадания координаты в прямоугольник.

## 3. Облако тоже встречается

Публикация Siemens и Microsoft от 24 октября 2024 описывает Industrial Copilot с Azure OpenAI. Это подтверждает существование облачного варианта, но не доказывает его превосходство для любого предприятия. [Официальная публикация](https://press.siemens.com/global/en/pressrelease/siemens-and-microsoft-scale-industrial-ai).

Решение зависит от ограничений данных, доступности связи, задержки, стоимости эксплуатации и качества модели. Можно сочетать локальный сбор/детекторы и облачный помощник. Для нашего демо выбираем локальную LLM, чтобы проверять работу без оплачиваемого облачного вызова.

## 4. Как появляется агент

Агент — код управления моделью и инструментами. Модель предлагает вызов функции; приложение проверяет аргументы и выполняет функцию; результат возвращается модели. Именно такой порядок описан в [Ollama tool calling](https://docs.ollama.com/capabilities/tool-calling).

На нашем предприятии инструменты читают карточку, события, допуски и состояние датчика. Не требуется обучать большую языковую модель с нуля, чтобы она получила актуальные данные V1. Данные даём инструментами. Если позже понадобятся текстовые регламенты, можно добавить поиск по документам; за два дня достаточно структурированного policy tool (инструмент агента).

## 5. Что значит «своя нейросеть»

| Вариант | Для нас |
| --- | --- |
| Написать адаптер и правила | Обязательно; это обычный код |
| Обучить небольшую MLP на наших эпизодах | Реалистичная экспериментальная часть Гриша (B2) |
| Дообучить готовую LLM | Сейчас не нужно; потребует качественных примеров и проверки |
| Обучить большую LLM с нуля | За два дня не берём |
| Запустить готовую LLM локально и дать tools (инструменты агента) | Работа Гаджи (B1) |

MLPClassifier — реализованный библиотекой многослойный перцептрон. Мы создаём признаки, датасет, обучаем веса и проверяем модель; честно называем это собственным обучением модели на готовой библиотеке. [Документация scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.neural_network.MLPClassifier.html).

## 6. Экономика и нагрузка

Локальное не равно бесплатное: нужны компьютер, RAM/VRAM, электроэнергия и поддержка. Облачное не равно отдельный дорогой сервер для каждого датчика: можно отправлять модели только выбранные происшествия.

Не сравниваем «свою MLP» и «API (способ обмена данными с сервером) большой LLM» по цене как взаимозаменяемые функции. У них разные задачи. Сравнение local LLM/cloud LLM делаем на одинаковых запросах: качество, latency (время ожидания ответа), оборудование, число запросов и затраты команды.

В MVP: один загруженный ML (машинное обучение) артефакт; окна движения вместо обращения к LLM на каждую точку; одна очередь агентных задач; короткая история; timeout (предельное время ожидания); кэш snapshot (снимок состояния данных). Мониторинг продолжает работу, даже если агент занят или выключен. Локальный API Ollama — способ связи с процессом на компьютере, не автоматически платный внешний API. [API introduction](https://docs.ollama.com/api/introduction).

## 7. Переход к настоящему предприятию

После хакатона: реальные схемы территории/единицы измерения, адаптеры оборудования, синхронизация часов, аутентификация/роли, резервирование, наблюдаемость, retention, защита данных, проверка модели на реальных эпизодах и пилот с диспетчерами. Команды физическому оборудованию требуют отдельного инженерного проекта и оценки безопасности.

Синтетическое качество не доказывает качество на заводе. Наша демонстрация показывает архитектуру и воспроизводимую экспериментальную реализацию; промышленную готовность не заявляем.

## 8. Что сказать жюри

«Мы разделили измерения, точные проверки, обученную модель паттернов движения и помощника диспетчера. Наша MLP обучена на воспроизводимых эпизодах, её ограничения и метрики открыты. Локальный агент получает факты инструментами и ссылается на исходные события. Его отключение не останавливает мониторинг».

Эту формулировку используем только после фактической реализации и проверки соответствующих частей. Работающее демо и доказательства важнее количества заявленных агентов.

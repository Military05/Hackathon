# Архитектура панелей v2 — три рабочих места и общий ИИ

Обновлено 7 октября 2026 под утверждённую цель. Это спецификация реализации, не готовое приложение. Полный контракт поведения теперь в [DISPATCH_OPERATIONS](DISPATCH_OPERATIONS.md) и [CONTRACTS v2](CONTRACTS.md); прежние site_area/summary предложения включены в требования.

## Экран и поток

Три профиля logistics/production/coordination, один backend/SQLite. Крупная карта своего сектора, постоянный журнал, общая краткая сводка, адресованные передачи/эскалации, карточка и ИИ-панель. Новые тревоги видны независимо от открытой карточки. Цвет дополнен текстом, звук требует разрешения пользователя; mute не прячет тревоги.

Симулятор/датчик → приём/хранение → точное правило либо MLP → Incident/участок/сектор → Notification/сводка → соответствующие окна. Один продолжающийся случай не дублируется на позиции, разные случаи параллельны. Оператор принимает один атомарно, ownership виден всем. Передача сохраняет прежнего до accept; эскалация сохраняет incident_id. Координация не ждёт LLM.

## Данные и модули

SiteArea/Sector/OperatorProfile/Presence/Incident/Transfer/DispatchHistory/Notification/Idempotency хранятся на сервере. Геометрия и связи в site.json. Основной участок фиксируется при обнаружении; unknown и общие дороги принадлежат coordination. Никакого определения участка по тексту модели.

Егор С.: src/core/events/rules/dispatch/scheduler, src/storage, схема, summary и API действий. Егор М.: src/interface/web, три профиля, курсор уведомлений и UI операций. Гаджи: src/agent/provider/tools/loop/queue/evidence, общий result по incident/snapshot. Гриша: simulator и MLP/extractor/artifact. Один server worker, короткие транзакции, одна запись SQLite; долгие ML/LLM вне транзакций и цикла приёма.

## ИИ и нейросеть

Одна общая Local-модель Bionic/LM Studio через фактически проверенный API; Ollama резерв. Одна running job, 20 queued, 120 секунд ожидания, 60 выполнения, 3 model requests/6 tools. Кэш incident+snapshot, новые evidence → stale, передачи ownership сами по себе не меняют snapshot. Инструменты только читают четыре согласованные функции. Ответ не назначает диспетчера, не подтверждает/закрывает тревогу, не управляет оборудованием.

MLP movement-v1 обучается отдельно, применяется на сохранённом Pipeline. Необычное движение не является прогнозом столкновения. Качество измерено на независимых синтетических эпизодах, ограничения открыты.

## Полный объём и приёмка

Передача, presence, reminder/escalation, восстановление после restart и совместная работа обязательны в финале. Аккаунты/смены/сложные права и промышленная отказоустойчивость не реализуются; header demo-профиля не аутентификация. Прогноз столкновений, рация и команды машинам исключены.

D1–D10, чистый клон, независимый повтор, весь offline показ и agent-off при работающем мониторинге — RELEASE gate. [План](TASK_03_PLAN.md), [BACKLOG](BACKLOG.md), [проверки](TESTING.md), [запуск](RUNBOOK.md).

[Исторический UI-пример](ui/README.md) не подключён к API/SQLite/модели и содержит внешние CDN-ресурсы. Он не подтверждает три рабочих места; финальный локальный UI создаётся в src/interface/web.

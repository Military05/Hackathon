# Контур v5 — первый запуск, команда и показ жюри

Инструкция для базовой поставки Егора С./М. от 7 октября 2026. Наблюдаемый
интеграционный код при подготовке документа:
`codex/factory-v5`, `50801c392eff751053d9c977e946132b60d1da15`.
Итоговый SHA и фактические результаты общей проверки записывает интегратор в
[RELEASE](RELEASE.md). Наличие инструкции не означает, что целевые ноутбуки,
внешний TLS или отдельные ML/ИИ-модули уже прошли приёмку.

## 1. Что вы запускаете

Один Python/FastAPI-сервер, одна SQLite и браузерные рабочие места. Сервер хранит
аккаунты, показания и историю. Браузер рисует общий план из site.json, получает
настоящие позиции раз в секунду и отправляет действия диспетчера на сервер.
Встроенный источник демонстрации относится к core; внешний симулятор, ML и
локальный ИИ — отдельные задачи Гриши и Гаджи и здесь не переписываются.

| Человек в продукте | Назначенный профиль | Ответственность |
| --- | --- | --- |
| Диспетчер 1 | dispatcher-1 / logistics | Логистика и склады |
| Диспетчер 2 | dispatcher-2 / production | Производство |
| Диспетчер 3 | dispatcher-3 / coordination | КПП и сохранённые резервные функции |
| Администратор | role=admin | Подтверждение аккаунтов, блокировка, назначение профиля |

Администратор — отдельная роль без четвёртого сектора. Для существующих
операторских действий его аккаунт использует профиль dispatcher-3. Создание
администратора выполняется только на компьютере сервера через CLI.

## 2. Подготовьте компьютер сервера

Предпочтительно использовать ноутбук с Ryzen 7 и 32 ГБ памяти. Для базового
сервера GPU не требуется; окончательный замер на обеих машинах остаётся задачей
Лии. Python 3.11+ и Git должны быть установлены. Первая установка зависимостей
требует интернета; дальнейший базовый показ использует локальные файлы.
Не ставьте Docker, новые модели или большие наборы данных ради этой версии.

Откройте PowerShell в папке, где хотите разместить проект:

```powershell
git clone https://github.com/Military05/Hackathon.git
cd Hackathon
git rev-parse HEAD
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

Если проект уже скачан и содержит вашу работу, сначала сохраните её в своей
ветке. Затем обновляйте main через `git pull --ff-only`; не используйте reset
или force push для удаления конфликтующих изменений.
Папка `.venv` содержит Python-зависимости, а `data/runtime` — локальную историю;
эти папки не отправляются в Git.

## 3. Создайте первого администратора

```powershell
.\.venv\Scripts\python.exe scripts/manage_users.py create-admin
```

Введите логин, имя, пароль и повтор пароля. Логин: 3–40 латинских букв, цифр,
точек, дефисов или подчёркиваний; регистр нормализуется. Имя: до 80 символов.
Пароль: 8–128 символов. Ввод пароля скрыт; его нет в аргументах команды или
истории PowerShell. Готового admin/admin не существует.

Пароль хранится как PBKDF2-HMAC-SHA256 с 600 000 итерациями и случайной солью.
Это хеш, а не открытый пароль или «кеш». Он вычисляется при входе/создании
аккаунта, а не при каждом обновлении карты.

Если назначаете собственную базу, задайте её перед созданием аккаунта и запуском:

```powershell
$env:DISPATCH_DB='data/runtime/my-demo-v5.db'
.\.venv\Scripts\python.exe scripts/manage_users.py create-admin
```

CLI и сервер должны использовать один путь. Администратор, созданный в другой
базе, не появится на рабочем сервере. Рабочую базу не удаляйте ради нового показа.
Список аккаунтов можно проверить командой:

```powershell
.\.venv\Scripts\python.exe scripts/manage_users.py list
```

## 4. Запустите сервер и войдите

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
```

Оставьте окно сервера работающим. Откройте `http://127.0.0.1:8000` и войдите
созданным администратором. Остановить сервер в его окне: Ctrl+C.
При повторном запуске аккаунты и журнал сохраняются; создавать администратора
заново не нужно. Если порт занят, используйте `-Port 8001` и соответствующий URL.

Авторизация включена по умолчанию. Не выключайте её для рабочего показа.
`DISPATCH_ENABLE_AUTH=0` оставлен только для изолированных тестов на localhost.
Стартовый скрипт запрещает такой режим с `-Lan`.

## 5. Подтвердите три диспетчерских аккаунта

1. Каждый участник открывает страницу в своём профиле браузера, нажимает
   «Подать заявку», вводит имя, логин и пароль, отправляет форму.
2. Регистрация получает `pending`; до подтверждения вход отклоняется. Пользователь
   не выбирает роль администратора или сектор в запросе регистрации.
3. Администратор нажимает «Администрирование», при необходимости «Обновить».
4. У каждой заявки выбирает «Логистика и склады», «Производство» или «КПП» и
   нажимает «Подтвердить».
5. Участники входят собственными аккаунтами. Рабочий сектор отображается сверху;
   изменение URL `?operator=…` не меняет назначение.

В панели можно изменить профиль активного пользователя и нажать «Сохранить»
или «Блокировать». Изменение статуса/профиля отзывает прежние сессии: участник
входит заново. Роль admin не выдаётся этой формой; последний активный
администратор защищён от блокировки, которая оставила бы систему без управления.
Журнал входов и административных действий раскрывается в той же панели.

Для локального создания заранее проверенного диспетчера есть CLI
`scripts/manage_users.py create-dispatcher`; он сразу создаёт активный аккаунт
и спрашивает dispatcher-1/2/3. На показе полезно проверить обычный путь заявки.

## 6. Не смешивайте аккаунты во вкладках

Обычные вкладки одного браузерного профиля используют общую cookie
`dispatch_session`. Вход другим аккаунтом в одной вкладке меняет сессию и
для остальных вкладок. URL оператора этого не исправляет.

Используйте три отдельных профиля браузера, три разных браузера либо три
компьютера. Несколько окон одного и того же режима инкогнито тоже могут
разделять общую сессию; не считайте их отдельными профилями без проверки.
Несколько вкладок одного аккаунта допустимы и считаются присутствием его профиля.

Страница отправляет `X-Expected-User` с ID вошедшего пользователя на чтение,
запись и CSV. Если другая вкладка сменила cookie, сервер возвращает
409 `session_identity_changed`, и старое рабочее место нужно обновить/перевойти.
Этот заголовок выявляет устаревшую вкладку; личность всё равно определяется
серверной сессией, а не заголовком.

## 7. Проверьте карту и обычную работу

При запуске включается «Штатная работа завода». В статусе число событий растёт,
машины П/V1, П/V2, С/V3 движутся и могут кратко останавливаться на погрузке.
Все клиенты видят один источник, одну историю и один выбранный сценарий.

- «Мой сектор» — склады слева, основные производственные цеха справа, КПП снизу.
  Кнопка плавно перемещает камеру за 0,85 секунды; при системном отключении
  анимаций наведение выполняется сразу. Управление сценариями находится над журналом.
  Дополнительные цеха также относятся к производству и доступны в общем виде.
- «Весь план» возвращает общую карту. Колесо/кнопки масштаба и перетаскивание
  позволяют изменить вид вручную; обновления данных не сбрасывают его.
- Оранжевые Z1/Z2 — зоны по индивидуальному допуску. V1 не имеет допуска,
  V2 может Z1, V3 — Z1/Z2. Красная Z3 со штриховкой запрещена всему транспорту.
- Секторы показаны тонкими контурами без заливки; голубой заливки нет.
- Подписи зданий остаются внутри обозначений; короткий вариант используется
  при малом масштабе. Сигналы датчиков и транспорта имеют время получения.
- Выбор происшествия подсвечивает его объект. Только «Показать на карте»
  переводит камеру к нему; мигание относится к выбранному происшествию.

Диагностика раскрывается под картой. Ручная проверка читает фактическое состояние,
не посылает выдуманный heartbeat и не гарантирует исправность физического датчика.
Свежая связь и свежая позиция проверяются отдельно.

## 8. Покажите «сначала люди, потом транспорт»

Выберите «Начало смены» и нажмите «Запустить сценарий». Это один общий запуск:

1. Фаза `gate_checks`: машины стоят в исходных точках, но их позиции и heartbeat
   продолжают приходить раз в секунду. Ожидание людей не выглядит потерей связи.
2. На 1-й, 3-й и 5-й секунде ACCESS-G1 сообщает разрешённые входы U1/U2/U3.
   В журнале КПП появляются три настоящие сохранённые записи.
3. После всех трёх уникальных разрешённых проходов фаза становится `transport`.
   Машины начинают движение с той же точки; счётчик событий транспорта растёт.
4. Проходы и последующие position принадлежат одной shift_id в серверной таблице
   корреляции. Публичные поля JSON Event не меняются; UI не сочиняет эту связь.

Ошибка при приёме прохода не открывает транспортную фазу. Остановка закрывает
эпизод; перезапуск сервера помечает прежнюю незавершённую смену `interrupted`
и не возобновляет её автоматически. История проходов остаётся.

## 9. Журнал, нарушение и действия

«КПП · проходы людей»: поиск по сотруднику/ID, вход/выход, допуск, период,
переход по страницам. Сценарий «Проход без допуска» проводит U4 через G1;
это фактически подтверждённый проход без права входа и штатный Incident.
Отказ карты, при котором человек остался снаружи, не записывается как проход.

«По журналу внутри» показывает только известных по полученным проходам людей.
Начальное присутствие неизвестно; число не является точной численностью всего
завода. Потеря ACCESS-G1 отдельно показывается пользователю.

Диспетчер открывает своё происшествие, принимает ответственность, записывает
реакцию и при необходимости передаёт готовому другому оператору. До подтверждения
передачи прежний оператор остаётся ответственным. Закрытие доступно текущему
ответственному после восстановления условия и без ожидающей передачи.
Dispatcher-3 не имеет общего права принимать необращённые случаи чужого сектора:
требуется адресованная эскалация/резерв или согласованная передача.

«Моя работа» считает успешные claim, завершённые исходящие передачи, close и
record_response. Ошибки запросов и непринятое предложение передачи не увеличивают
число завершённых действий. Общая история сохраняется на сервере.

## 10. Выгрузка CSV

- «CSV · 200» КПП сохраняет до 200 самых новых записей по выбранным фильтрам,
  начиная с первой страницы, независимо от текущей страницы просмотра.
- «Действия · CSV» сохраняет до 1000 последних действий текущего профиля.
  API допускает limit до 2000; `scope=all` доступен только роли admin.
- UTF-8 с BOM подходит табличным редакторам; кавычки/запятые экранируются,
  начальные формулы нейтрализуются. CSV — ограниченная выгрузка, а не резервная
  копия всей SQLite или экспорт всех записей за всё время.

## 11. Минимальная защита для жюри

| Проверка | Ожидаемый результат |
| --- | --- |
| Открыть `/api/assets` без входа в отдельном чистом профиле | 401, данные не выдаются |
| Зарегистрировать аккаунт и попробовать вход до подтверждения | Заявка pending, вход 403 |
| Подтвердить и назначить профиль через администратора | Вход разрешён, сектор назначен сервером |
| Диспетчеру открыть `/api/admin/users` | 403 admin_required |
| Изменить `?operator=dispatcher-3` у диспетчера 1 | Личность/полномочия остаются dispatcher-1 |
| Изменить cookie входом другого пользователя в том же профиле | Старая страница получает 409 session_identity_changed |
| Выйти и повторить запрос защищённых данных | 401, старая сессия отозвана |
| Изменяющий запрос без CSRF или с чужого Origin | 403 |
| Внешний POST событий без настроенного source key | 503; с неверным ключом после настройки — 401 |

Проверки CSRF, отзыва сессии, лимита попыток и source key удобно дополнить
автоматическим тестом на отдельной временной базе:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests/runtime -p 'test_auth.py' -v
```

Это тестовая проверка, не подменяющая живой показ. После пяти неверных попыток
входа за минуту следующая получает 429; не повторяйте вход автоматически.
В аудит не сохраняются пароли, сырой session token, CSRF или source key.
Корректная формулировка для защиты: «Базовая авторизация, разграничение доступа,
защита изменяющих запросов и журналирование». Промышленная сертификация отсутствует.

## 12. Если понадобятся внешние события или другой ноутбук

Встроенному источнику ключ не нужен. Для внешнего HTTP-адаптера владелец сервера
генерирует случайный секрет и передаёт его владельцу источника защищённо:

```powershell
$env:DISPATCH_SOURCE_KEY = & .\.venv\Scripts\python.exe -c 'import secrets; print(secrets.token_urlsafe(32))'
```

Секрет не печатается отдельной командой, не включается в Git или frontend.
Внешний клиент использует `X-Source-Key`; Гриша/Гаджи обновляют свои адаптеры
отдельно по согласованному контракту. До этого встроенное демо продолжает работу.

Для другого компьютера нужен доверенный HTTPS-сертификат с адресом сервера:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Lan -TlsCert 'E:\certs\factory.crt' -TlsKey 'E:\certs\factory.key'
```

Все браузеры должны доверять сертификату; отключение его проверки не считается
приёмкой. Ключ сертификата не коммитится. Обычный удалённый HTTP отклоняется.
Проверенный шифрующий туннель допустим только при отдельной настройке владельцем;
`DISPATCH_TRUST_ENCRYPTED_TUNNEL=1` не создаёт VPN и сам не шифрует соединение.
Стартовый скрипт не открывает маршрутизатор и не настраивает Firewall.
Удалённый TLS/туннель и целевые ноутбуки — **NOT RUN** до отдельного отчёта.

## 13. Когда что-то не работает

| Сообщение/симптом | Действие |
| --- | --- |
| Первый администратор не создан | Проверить DISPATCH_DB и создать admin в той же базе |
| Заявка ожидает подтверждения | Администратор назначает профиль и подтверждает |
| Сессия истекла/аккаунт заблокирован | Войти снова; администратор проверяет состояние |
| session_identity_changed | Разделить профили браузера, обновить старую страницу |
| 429 входа | Подождать минуту, проверить ввод; не запускать цикл повторов |
| Пустой журнал КПП в normal | Нормально: обычный сценарий не выдумывает людей; запустить shift |
| Машины стоят в gate_checks | Дождаться трёх подтверждений; при error прочитать статус источника |
| Датчики offline после «Остановить» | Это прекращение пакетов; запуск normal возвращает реальные сигналы |
| ИИ/ML недоступны | Отдельные модули ещё не поставлены/не включены, основа работает |
| encrypted_transport_required | Использовать доверенный HTTPS/проверенный туннель |
| Порт занят | Запустить с -Port и открыть соответствующий адрес |

## 14. Что ещё проверяет команда

Лия: три независимых входа, одновременно открытые случаи, сохранность текста,
передача/резерв, restart, фильтры/CSV, ложные тревоги, обе целевые машины.
Гриша: внешний источник и реальный ML-артефакт. Гаджи: реальный runtime агента,
сессии/CSRF его HTTP-клиента, evidence и tool trace. Координатор фиксирует полный
SHA проверки и выполняет итоговое объединение в main после необходимой приёмки.

База обычно получает 3 position + 3 heartbeat в секунду; проходы добавляют
единичные access. Карта интерполирует принятые координаты до 15 кадров/с.
Один worker/SQLite, без GPU для этого пути. История и аудит растут при длительной
работе; один удачный тест не доказывает скорость на всех устройствах.
Полный ML/ИИ end-to-end и отсутствие ошибок на целевых устройствах не заявляются.

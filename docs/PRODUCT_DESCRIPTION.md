# Контур: полное описание продукта и его работы

Актуально на 8 октября 2026. Основа описания — опубликованный main
`35c9e7b0685a44894681c013c75fdf3199565233`: карта v6, правила, аккаунты,
КПП и интегрированные модули MLP/ИИ. [Краткое описание](PRODUCT_BRIEF.md).

## 1. Назначение

«Контур» — учебная система мониторинга автомобильного завода. Она показывает
движение транспорта и состояние датчиков, проверяет допуски и маршруты,
создаёт происшествия и помогает диспетчерам их обработать. Несколько пользователей
работают с одной картой и общей историей через браузер.

Данные текущих сценариев синтетические: транспорт, проходы людей и сигналы
создаёт серверный источник. Это рабочая симуляция обработки событий.
Управление настоящими воротами и машинами, подтверждение физического ДТП
и промышленная оценка риска в продукт не входят.

## 2. Из чего состоит система

| Часть | Что делает |
| --- | --- |
| Браузерный интерфейс | Показывает карту, сценарии, датчики, происшествия, КПП и действия |
| Сервер Python/FastAPI | Принимает данные, проверяет правила и права пользователей |
| SQLite | Хранит события, происшествия, пользователей, сессии, проходы и аудит |
| Встроенный источник | Двигает три машины и отправляет position/access/heartbeat |
| Серверные правила | Проверяют зоны, маршруты, пересечения, доступ и потерю связи |
| MLP, дополнительный режим | Оценивает необычность движения по окнам координат |
| Локальный ИИ-агент, дополнительный режим | Объясняет выбранный случай по данным разрешённых инструментов |

Базовый запуск включает авторизацию, встроенное движение, правила и интерфейс.
ML и ИИ доступны в коде, но включаются отдельным запуском и требуют своих
зависимостей и модели. Их отсутствие не останавливает базовый мониторинг.

## 3. Карта предприятия

План содержит 18 объектов: офис и КПП, склады сырья, комплектующих и готовых
автомобилей, инструментальный склад, прессовый, сварочный, окрасочный и сборочные
цеха, ОТК, инженерный корпус, столовую, энергоцентр, насосную, медпункт и пожарный
пост. Здания соединены системой из 34 дорожных линий с отдельными подъездами.

Это собственный условный план с координатами от 0 до 100. Он не использует
GPS, спутниковую подложку или сервер карт. Расстояния в правилах выражены
в единицах плана. Названия сокращаются, если полное имя не помещается в здание.

Транспорт показан символами: V1/V2 — погрузчики, V3 — служебная машина.
Рядом видны датчик и время последнего сигнала. Личные маршруты связывают
склады W1/W2, производство P1/P2 и служебный участок E1. Переключатель
«Маршруты» управляет линиями; выбор машины выделяет её путь и показывает
назначение, допуски, запреты и свежесть координат.

Пять пунктирных пешеходных путей обозначают связи между объектами. Эти линии
сами не создают людей, проходы или датчики: события прохода приходят через КПП.

| Обозначение | Смысл |
| --- | --- |
| Красные Z3/Z6 | Въезд запрещён всему транспорту |
| Красная Z4 | Въезд запрещён служебному транспорту |
| Красные Z5/Z7 | Въезд запрещён погрузчикам |
| Оранжевые Z1/Z2 | Въезд разрешён только по индивидуальному допуску |
| Тонкий контур сектора | Область ответственности диспетчера, без голубой заливки |

Наведите мышь на зону для её правила. Красный запрет действует на указанный
тип даже при наличии другого допуска. Разрешение в одну зону не разрешает остальные.

«Мой сектор» плавно приближает область вошедшего диспетчера, «Весь план»
возвращает обзор. Обновления данных сохраняют положение камеры. Выбор
происшествия подсвечивает связанные объекты; «Показать на карте» наводит
камеру. При пересечении выделяются обе машины. Устаревшая точка означает
последнее известное положение, а не подтверждённое текущее место.

## 4. Пользователи, вход и администратор

| Профиль | Основная ответственность |
| --- | --- |
| Диспетчер 1 | Логистика и склады |
| Диспетчер 2 | Производство |
| Диспетчер 3 | КПП, офис и предусмотренные функции координации |
| Администратор | Заявки, назначение профиля, блокировка и аудит аккаунтов |

Регистрация создаёт заявку со статусом «Ожидает подтверждения». Пользователь
ещё не может работать. Администратор открывает «Администрирование», назначает
один из трёх профилей и подтверждает доступ. Администратор создаётся локальной
командой на сервере; в публичной регистрации нельзя самостоятельно получить его роль.
Отдельного четвёртого сектора для администратора нет.

После входа сервер выдаёт сессию и определяет профиль по ней. Изменение адреса
`?operator=...` не меняет роль. Для трёх одновременных аккаунтов нужны разные
профили браузера, браузеры либо устройства: обычные вкладки разделяют cookie.

«На смене» сообщает готовность диспетчера. Если снять галочку, рабочее место
публикует состояние отсутствия, которое учитывают резерв и переназначение.
Выход или закрытие страницы не освобождают принятую ответственность автоматически.

## 5. Как данные превращаются в происшествие

1. Источник отправляет событие: координаты машины, подтверждённый проход или сигнал связи.
2. Сервер проверяет идентификаторы, структуру, время и координаты.
3. Событие сохраняется в SQLite; повтор с тем же ID не создаёт повторных действий.
4. Сервер обновляет состояние объекта/датчика и проверяет соответствующие правила.
5. При нарушении создаётся карточка происшествия со временем, местом, типом,
   важностью, ответственным сектором и подтверждающими событиями.
6. Браузеры получают актуальную карту и журнал; диспетчер открывает карточку.
7. Его действия записываются в общую историю с проверкой полномочий и версии карточки.

Историческая позиция не откатывает более новую текущую позицию. Сохранённые
события служат доказательствами. Плавное движение значка в браузере лишь
отображает данные; по кадрам клиентской анимации тревоги не создаются.

## 6. Датчики и диагностика

Всего шесть источников: POS-V1/POS-V2/POS-V3 для координат, ACCESS-G1 для
проходов КПП, ACCESS-O1 для доступа к офису, HB-QA для контроля связи.
Встроенный источник передаёт координаты/сигналы примерно раз в секунду.
Отсутствие проходов при работающем heartbeat является нормальной ситуацией.

Система различает связь и измерение. Датчик может передавать heartbeat,
но не давать свежих координат. Поэтому «На связи» само по себе не доказывает
актуальность позиции. По текущей конфигурации связь и координаты устаревают
через 5 секунд; для первого появления датчика есть начальное ожидание 10 секунд.

В «Датчиках и диагностике» можно открыть источник, увидеть последний пакет,
heartbeat, измерение и причину внимания. «Проверить сейчас» перечитывает сервер.
Автопроверка каждые 30 секунд анализирует уже имеющийся снимок состояния.
Можно включить короткий звук проверки вместе с общим звуком страницы.

Это проверка связи и свежести данных. Она не отправляет физический тест прибору
и не создаёт выдуманный heartbeat. Локальные наблюдения панели относятся к
текущей вкладке; серверная история происшествий хранится в базе.

## 7. Какие условия обнаруживаются

| Условие | Как оно определяется | Когда условие восстанавливается |
| --- | --- | --- |
| Въезд в запрещённую зону | Свежая координата внутри зоны, запрещённой машине/типу | Две последовательные свежие позиции вне зоны |
| Проход без допуска | Подтверждённый вход сотрудника без допуска к объекту | Это разовое зафиксированное событие; требуется обработка карточки |
| Потеря связи | Новые пакеты не поступают дольше порога | Источник реально прислал свежий пакет |
| Отклонение от маршрута | Две свежие позиции дальше 2 единиц от личного пути | Две свежие позиции снова на допустимом пути |
| Пересечение транспорта | Свежие близкие по времени положения/отрезки сближаются до суммы радиусов | Две свежие проверки подтверждают разделение |
| Модельное подозрение, при ML | MLP оценивает достаточное окно движения как необычное | Два достаточных нормальных окна; недостаточные данные не считаются нормой |

Для пересечения стандартные радиусы — по 0,5 единицы плана. Проверяется общий
интервал времени: пересечение дорог в разное время не является этим условием.
Между соседними измерениями симуляция предполагает прямое движение.
Это наблюдаемое сближение в учебной модели, а не вероятность физического ДТП.

При потере свежих данных условие может стать «Нужно проверить». Отсутствие
новой координаты не означает, что машина покинула опасный участок.
Одно продолжающееся условие не создаёт новую карточку на каждый пакет.
Повторное нарушение после восстановления может создать новый случай.

## 8. Работа диспетчера с происшествием

Карточки создаёт система автоматически. Она определяет сектор по месту события,
но не назначает фиктивного человека: диспетчер принимает ответственность сам.
По умолчанию рабочее место показывает свой сектор и адресованные ему случаи;
«Всё предприятие» расширяет просмотр. Просмотр не даёт права принять любую карточку.

Обычный порядок: открыть случай → посмотреть объекты на карте → принять
ответственность → связаться с нужной ролью → записать реакцию → завершить
обработку после восстановления. Запись «Связался» фиксирует сообщение оператора;
приложение само не звонит, не отправляет сообщение и не управляет оборудованием.

У карточки два разных состояния. «Активно/Восстановлено/Нужно проверить»
описывает наблюдаемое условие. «Не принято/Принято/Завершено» описывает работу
человека. Машина может уже выехать, а случай всё ещё ждать диспетчера.
Завершение блокируется при активном/неизвестном условии и незавершённой передаче.

Для передачи выбирают получателя и указывают причину. Ответственность остаётся
у прежнего диспетчера, пока получатель не примет передачу. Напоминания,
эскалации и резерв помогают обнаружить оставленную работу. Эскалация является
уведомлением, а не новым физическим происшествием. Сервер проверяет готовность,
сроки и полномочия; одновременное принятие двумя людьми даёт одного владельца.
Отсутствие оператора создаёт уведомление; восстановительное переназначение
выполняет готовый резерв вручную после серверной проверки.

Поиск/фильтры позволяют выбрать тип, состояние, источник и место. «Моя работа»
считает успешные принятия, передачи, завершения и записанные реакции.

## 9. КПП и начало смены

ACCESS-G1 фиксирует подтверждённые входы/выходы с сотрудником, временем и допуском.
U1/U2/U3 демонстрируют разрешённые проходы, U4 — проход без допуска. Это факт
прохода; отказ карточке без пересечения КПП не равен такому событию. Нарушение
создаёт подтверждённый вход без допуска; выход новой такой тревоги не создаёт.

В сценарии «Смена персонала» сначала проверяются три уникальных разрешённых
входа. Только после результата 3/3 начинается транспорт. Проходы и движение
связаны одним номером смены. Во время проверки людей heartbeat и координаты
продолжают поступать; источник не изображает потерю связи из-за ожидания.

Журнал КПП поддерживает поиск, направление, допуск, период и страницы.
Оценка количества людей внутри строится по последним полученным проходам:
начальное присутствие неизвестно, поэтому это не точная перепись предприятия.

## 10. Сценарии и проверка функций

Панель «Движение и сценарии» расположена над происшествиями. Один выбранный
запуск действует на весь сервер и всех диспетчеров. Под выбором указан ожидаемый
результат; реальные карточки создаются только после обработки событий.

Есть 13 сценариев: штатная работа, доставка сырья/отгрузка, смена персонала,
технический объезд, въезд в закрытую зону, проход без допуска, потеря связи,
несколько происшествий, отклонение маршрута, пересечение транспорта,
безопасный разъезд, погрузчик в производственной зоне и служебная машина
в запрещённой зоне. Пошаговый показ и ожидаемые исходы — [FACTORY_V6](FACTORY_V6.md).

Некоторые нарушения появляются после подъезда машины: подождите до 45 секунд.
Отклонение маршрута может сопровождать другое нарушение. Новый сценарий
сохраняет историю старых карточек; штатный запуск означает отсутствие новых
нарушений этого запуска. Проверяйте время обнаружения и фильтр типа.
«Остановить» прекращает передачу; позже потеря связи датчиков становится ожидаемой.

## 11. Журналы и CSV

SQLite сохраняет исходные события, проходы, действия и обработку происшествий.
«Скачать журнал КПП» экспортирует до 200 последних проходов с выбранными
фильтрами. «Скачать журнал действий» отдаёт до 1000 собственных записей;
API допускает максимум 2000, общий журнал доступен администратору.

Имена файлов, колонки и значения подписаны по-русски. Формат — UTF-8 с BOM,
разделитель `;`, время МСК с секундами для аудита. Строки, похожие на формулы
Excel, экранируются. Если колонки не разделились, импортируйте через
«Данные → Из текста/CSV», UTF-8, разделитель «точка с запятой».

## 12. Минимальная защита

Пароли длиной 8–128 символов хранятся как PBKDF2-HMAC-SHA256-хеши с солью.
Сессии и права проверяет сервер; изменения требуют CSRF-токена и допустимого
Origin. Есть ограничение попыток входа, отзыв сессий при блокировке,
проверка аккаунта устаревшей вкладки и журнал входов/административных действий.

Внешняя отправка событий требует отдельный X-Source-Key. Он не даёт права
диспетчера. Аккаунты, базы, `.env`, приватные ключи и большие веса LLM
не публикуются в Git. Это базовая защита учебного продукта; независимый
промышленный аудит безопасности не проводился.

## 13. Как работают MLP и локальный ИИ

Интеграция включена в main отдельной поставкой владельцев. MLP использует
обученный артефакт в `models/movement-v1`, CPU и признаки движения одного объекта:
скорость, остановки, длину пути, шаги и повороты. Сервер оценивает окна
последних 10 секунд каждые 5 секунд, когда достаточно уникальных координат,
и сохраняет результат с подтверждающими Event.

У модели известны ложные подозрения на штатных normal/service маршрутах v6,
описанные в [отчёте интеграции](AI_MLP_V5.md). Модельное подозрение требует
проверки диспетчера и не отменяет подтверждённое серверное нарушение.
Число score не означает вероятность аварии.

Локальная Qwen3 4B запускается через проверенный владельцами runtime Bionic.
По кнопке анализа агент получает снимок выбранной карточки, историю событий,
допуски и состояние датчиков через разрешённые инструменты. Для пересечения
в снимок входят обе машины. Ответ содержит факты, гипотезы, рекомендации
и ссылки на исходные события; изменение фактов помечает прошлый анализ устаревшим.

Очередь ограничена одним выполняемым и двумя ожидающими заданиями; выполнение
ограничено 60 секундами, тремя запросами модели и шестью вызовами инструментов. Агент
не принимает/закрывает случаи, не меняет допуски и не управляет оборудованием.
Если модель недоступна, интерфейс показывает это, а ручная работа продолжается.
Настройка, зависимости, отчёты владельцев и запуск — [AI_MLP_V5](AI_MLP_V5.md).

При подготовке этого описания текущий preview на порту 8773 работал в базовом
режиме: rules=ready, ml/agent=unavailable. Наличие модулей в Git не включает
их в уже работающий процесс; новый запуск моделей в рамках описания не выполнялся.

## 14. Запуск, другие устройства и мощность

Первый запуск: установить зависимости → создать администратора в выбранной
базе → запустить сервер → подтвердить заявки участников. Точные команды —
[README](../README.md) и [RUNTIME_QUICKSTART](RUNTIME_QUICKSTART.md).
Администратор текущего демонстрационного сервера уже создан локально;
в свежем clone нужен собственный bootstrap. Пароль не входит в документацию Git.

Для базового режима используется один Python worker, SQLite, шесть источников
с частотой 1 Гц и карта с интерполяцией до 15 кадров/с. GPU, Docker и отдельный
сервер карты ему не нужны. История растёт на диске по мере работы.
Режим LLM тяжелее: отчёт владельцев для RTX 4060 не доказывает такую же скорость
на ноутбуках с 8 ГБ RAM/GTX 1650 или 32 ГБ RAM/Radeon 780M.

На другом ноутбуке достаточно браузера, если он подключается к тому же серверу.
Тогда работают те же аккаунты и общая история. Новый сервер после clone создаёт
свою SQLite и не получает старые пароли. `127.0.0.1` на другом компьютере
указывает на него самого; для общего доступа нужен доверенный HTTPS либо
проверенный защищённый туннель. [REMOTE_CLIENT_V6](REMOTE_CLIENT_V6.md).

Результаты базовых проверок — [RELEASE](RELEASE.md); результаты MLP/Qwen
отдельного исполнителя — [AI_MLP_V5](AI_MLP_V5.md). При подготовке описания
повторные функциональные тесты и запуск моделей не выполнялись.
Длительная нагрузка, целевые ноутбуки, общий показ трёх клиентов и удалённое
TLS-соединение требуют своей приёмки.

этап; для состояния нейросетей используйте текущий main и AI_MLP_V5.

## Интеграция

Зафиксировать head (ветка или версия с предлагаемыми изменениями) main и feature/beta1-f1; один оператор вливает main → F1; Лия (QA — тестировщик) проверяет этот SHA без изменений. PR (запрос на объединение изменений) F1 → main merge (объединение веток) commit (сохранение изменений в истории Git). После merge повторный smoke (короткая проверка запуска и основного сценария). Если head изменился после проверки Лией (QA — тестировщик), повторить затронутую проверку. Не force-push main.

## Короткая защита

Три рабочих места → normal → D1–D3 → три одновременных случая → claim/передача/эскалация → D4 и реальные метрики → агент запрашивает историю/допуски → объяснение с evidence → выключение LLM при работающем мониторинге. Отдельно ограничения: demo (демонстрационные данные) данные, нет промышленного пилота, score (оценка модели) не вероятность аварии.
